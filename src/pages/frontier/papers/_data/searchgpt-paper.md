## 研究动机

传统搜索引擎的工作流程：Query → 倒排索引检索 → BM25/向量排序 → 结果展示

这种流程存在明显局限：
- 无法理解复杂的自然语言查询意图
- 结果以链接列表形式呈现，用户需要自行阅读和综合
- 无法处理需要多步推理的查询

SearchGPT将LLM引入搜索全链路，实现了真正意义上的"理解式搜索"。

## 系统架构

### 三阶段流水线

**阶段一：Query理解与扩展**

```
原始Query → LLM → {
  意图分类: [信息查询/导航/事务]
  实体识别: [人物/地点/事件]
  查询扩展: [同义词/相关概念]
  子问题分解: [Q1, Q2, Q3]
}
```

**阶段二：检索与重排**

- 使用扩展后的多个查询并行检索
- 基于LLM的交叉编码器（Cross-Encoder）进行精细重排
- 融合BM25稀疏检索和向量稠密检索结果

**阶段三：答案生成**

基于检索到的文档，使用RAG（检索增强生成）技术生成结构化答案，并标注信息来源。

## 关键技术

### 查询意图理解

使用微调后的LLM对查询进行多维度分析：

| 维度 | 示例 |
|------|------|
| 时效性 | 实时/历史 |
| 专业度 | 通俗/专业 |
| 答案类型 | 事实/观点/步骤 |

### 文档相关性评分

$$\text{score}(q, d) = \alpha \cdot \text{BM25}(q, d) + \beta \cdot \text{Dense}(q, d) + \gamma \cdot \text{LLM-Rerank}(q, d)$$

### 答案生成与引用

生成答案时，每个句子都关联到具体的来源文档，支持用户验证信息真实性。

## 评测结果

在BEIR基准测试集上的表现：

| 数据集 | BM25 | DPR | SearchGPT |
|--------|------|-----|-----------|
| NQ | 30.2 | 41.5 | 52.8 |
| TriviaQA | 60.1 | 67.3 | 74.6 |
| HotpotQA | 25.4 | 38.2 | 49.1 |

## 局限性与未来工作

- **幻觉问题**：LLM可能生成与检索文档不符的内容
- **实时性**：LLM推理延迟较高，需要进一步优化
- **多语言支持**：目前主要针对英文优化

未来将探索更轻量级的模型架构和更高效的推理方案。
