# 1.4　生成式推荐的定义与分类框架

## 1.4.1　本节定位：从范式判断到正式定义

§1.3 末尾留下了一个尚未回答的问题——经历了"特征—打分—生成"三阶段渗透之后，学界开始把"生成式推荐"作为独立研究方向看待，但当我们说"生成式推荐"时，到底在指哪一类系统？这个问题不澄清，本书后续九章就缺少一根贯穿的概念主轴。本节的任务，就是把这根主轴竖起来：先给出生成式推荐（Generative Recommendation）的严义定义，再厘清它与"LLM 辅助推荐"等近邻概念的边界，最后把这一新范式按生成机制划分为三大类，并用一张全书纲领性对照表把后续各章对接到这三类范式上。可以先建立一个直觉性判据——在传统推荐里，模型的角色是"评委"，对一份事先准备好的候选名单逐一打分；在生成式推荐里，模型的角色是"作者"，直接把推荐结果当作一段内容写出来。本节的全部讨论，都是把这一直觉转化为可操作的定义、可分类的方法、以及可对应到全书章节的路线图。

## 1.4.2　正式定义：生成式推荐的严义与宽义之辨

"生成式推荐"在 2017—2022 年间是一个含义模糊的术语。早期工作（2017—2019）使用 GAN 与 VAE 做推荐数据增强或表示学习，习惯上也称作"生成式推荐"——这是该术语的**宽义**，只要在推荐流程中使用了任意生成模型（VAE / GAN / Diffusion / LLM），都被纳入。宽义的问题在于过度泛化：仍走"召回—粗排—精排"判别式骨架、只是在某一层换了生成模型的系统，与一个直接生成物品标识序列、彻底取消候选打分的系统，被装进了同一个口袋——这种归类不利于讨论范式差异。

针对这一含混，2023 年 Li 等人发表的综述 [REF-007]（LREC-COLING 2024 接收，arXiv:2309.01157）首次对"生成式推荐"给出了被学界广泛引用的严义定义。该综述的核心观点是：与其把推荐流程拆成多个阶段（打分 + 重排），不如借助 LLM 等生成模型，把整个推荐过程压缩到一个阶段——直接从全量物品池中生成推荐结果。本书自此遵循这一严义定义：

> **定义 1.1（生成式推荐，严义）**　生成式推荐系统直接生成推荐物品或推荐相关内容，无需再为每一个候选物品逐一计算排名分数（[REF-007]）。

这个定义的关键词只有一个——"直接生成"。在严义之下，把推荐过程压缩为单阶段并把动作空间扩展到全量物品池，是判定一个系统是否为生成式推荐的形式判据。下面用一张三维度对比表把它与传统推荐放在一起看，定义的张力会更清晰。

**表 1-4　传统推荐与生成式推荐的本质对比**

| 维度 | 传统推荐 | 生成式推荐 |
|---|---|---|
| 处理流程 | 多阶段过滤（召回→粗排→精排） | 单阶段直接生成 |
| 候选集处理 | 为每个候选物品逐一计算分数 | 直接生成物品标识或内容序列 |
| 动作空间 | 上游级联交付的候选集（10²–10⁴ 量级） | 隐式覆盖全物品库（10⁶–10⁹ 量级） |
| 输出形式 | 排序分数列表 | 物品 ID 序列 / 物品向量 / 自然语言物品描述 |
| 核心机制 | 判别式 AI（分类 / 回归 / 学习排序） | 生成式 AI（自回归 / 扩散 / LLM 条件生成） |

定义 1.1 还有一个常被忽略的推论——既然生成式推荐"无需对每一个候选打分"，也就意味着它**理论上不需要候选集前置**。在传统级联架构中，召回为后续阶段限定了动作空间（即"打分"的对象集合）；而在生成式推荐中，模型的动作空间在原则上等于全部物品库。这一点在工业落地时会因约束解码（Constrained Decoding）等工程手段被部分收紧，但作为范式判据，"是否仍依赖候选打分"是最简洁的检验。

2025 年 Yu 等人发表的综述 [REF-006]（arXiv:2510.27157）从 Data / Model / Task 三个维度组织了对生成式推荐的全景梳理，把这一范式的核心刻画进一步精炼为：**生成式推荐将推荐问题重新概念化为生成任务，而不是判别评分任务**。这一精炼版本与定义 1.1 在语义上完全一致，本书后续涉及方法对比时会同时引用两种表述。

### 1.4.2.1　与"LLM 辅助推荐"的边界辨析

定义 1.1 之外，还有一个易混淆的近邻概念需要厘清——LLM 辅助推荐（LLM-augmented Recommendation）。这一辨析对界定本书核心范畴尤为重要，否则任何使用了 LLM 的推荐系统都可能被错误地归入"生成式推荐"。2024 年 Zhang 等人发表的综述 [REF-068]（arXiv:2410.19744）给出了一个清晰的二分法：

- **非生成式 LLM 推荐**：LLM 被用作特征提取器、语义编码器或打分增强器；推荐流程的判别式骨架（召回—候选—打分—排序）保持不变，LLM 只是把其中某一层换成"加粗的 BERT"。这类系统仍为每一个候选物品计算分数，因此**不属于**严义生成式推荐。
- **生成式 LLM 推荐**：LLM 直接把用户上下文映射到物品标识或物品内容，输出本身即推荐结果，不再需要候选打分。这类系统**属于**严义生成式推荐，且是其下三大范式中"LLM 端到端"一类的代表实现。

[REF-068] 在「Scheming and Utilizing」一章中正式以「Non-Generative LLM-based Recommendation」与「Generative LLM-based Recommendation」二分给出上述区分，并把后者纳入论文标题"迈向下一代"（Towards Next-Generation）的演进取向。把上述区分压缩为可操作的一句话判据：

> **判据 1.1（生成式推荐的最简检验）**　给定一个推荐系统，如果去掉它对"每个候选物品分别打分"的步骤之后，系统仍能产出推荐结果，则它属于生成式推荐；否则不属于。

判据 1.1 与定义 1.1 等价，但更便于工程师在阅读论文与系统设计文档时快速判别。在本书的章节安排中，第 6 章「LLM 端到端推荐」聚焦"生成式 LLM 推荐"；而"非生成式 LLM 推荐"——LLM 作为特征工厂或打分员的工作——将在第 8 章「跨场景应用」中作为对比基线讨论，不是本书的核心范式。

## 1.4.3　统一形式化：把三大范式装进同一个概率框架

在进入分类之前，先用一组统一的数学符号刻画"生成式推荐"——这样后续讨论三大范式时，差别就只剩下"如何参数化条件概率"这一项，叙事可以集中。

设用户上下文为 $x$（例如历史交互序列、用户画像、自然语言指令），推荐输出为 $y$（可以是物品标识 token 序列、物品向量、或自然语言物品描述），模型参数为 $\theta$。生成式推荐的统一形式可以写作：

$$
\hat{y} \;=\; \arg\max_{y \in \mathcal{Y}}\; P_{\theta}\!\left(y \,\big|\, x\right). \tag{1.8}
$$

公式 (1.8) 中，$\mathcal{Y}$ 是合法输出空间（在严义生成式推荐中，$\mathcal{Y}$ 与全物品库存在显式或隐式的等价映射，而非传统级联中由召回提供的候选集），$P_{\theta}(y\mid x)$ 是模型对给定上下文的输出条件概率。$\arg\max$ 的实现方式可以是贪心解码、Beam Search、约束解码、扩散去噪采样或自然语言生成——这取决于具体的范式实现，但目标都是从 $P_{\theta}$ 中选出一个高概率的合法输出 $\hat y$。

公式 (1.8) 的物理意义是把"推荐"重新表述为一个**条件生成问题**。它与 §1.2 公式 (1.5) 双塔点积、§1.3 公式 (1.7) P5 自回归之间的关系是这样的——双塔点积可视为"先计算每个候选 $i$ 的 $\langle u, i\rangle$ 再取 top-k"，本质是在有限候选集上做判别打分；公式 (1.8) 则把候选集隐式融进 $P_{\theta}$ 的归一化分母中，模型不再为每个候选单独打分，而是直接采样高概率输出。这一形式不指定 $P_{\theta}$ 的具体参数化——把不同的参数化方式代入公式 (1.8)，就得到不同的生成式推荐范式。

下面给出三种主流参数化方式，对应本书将贯穿讨论的三大范式：

- **自回归参数化**：把 $y$ 表示为离散 token 序列 $y_{1:T}$，按链式法则分解条件概率。
$$P_{\theta}(y_{1:T}\mid x)\;=\;\prod_{t=1}^{T} P_{\theta}\!\left(y_t\,\big|\,y_{<t}, x\right).\tag{1.8a}$$

- **扩散参数化**：通过马尔可夫链 $y^{(K)}\!\to\!y^{(K-1)}\!\to\!\cdots\!\to\!y^{(0)}$ 由噪声逐步去噪到目标。
$$P_{\theta}(y\mid x)\;=\;\int p\!\left(y^{(K)}\right)\prod_{k=1}^{K} P_{\theta}\!\left(y^{(k-1)}\,\big|\,y^{(k)}, x\right)\,\mathrm{d}\,y^{(K{:}1)}.\tag{1.8b}$$

- **LLM 端到端参数化**：把 $y$ 表示为自然语言 token 序列，由预训练大语言模型给出条件概率，形式上同 (1.8a)，但 $P_{\theta}$ 由开放世界预训练得到，且 $y$ 不限定为物品 ID。

读者可以把这一组公式看作本节的"语法"——后续每讨论一个具体方法，都可以追问它把 $P_{\theta}$ 参数化成哪一种形式、合法输出空间 $\mathcal{Y}$ 又是怎样定义的。

## 1.4.4　三大范式：自回归生成、扩散生成、LLM 端到端

按照对 $P_{\theta}$ 的参数化方式，本书将生成式推荐切分为三大范式。这一划分与 [REF-006] 的 Model 维度分类（LLM-based / Large Recommendation Models / Diffusion）直接对齐，与 [REF-070]（Gen-RecSys，KDD 2024 Tutorial）对生成模型在推荐中应用的横向梳理相互印证。需要说明的是，[REF-070] 的横向覆盖比本书更宽——它同时讨论了 VAE、GAN 等更早期的生成模型；本书把 VAE / GAN 相关工作并入"早期生成方法"在第 12 章里点到为止，不作为独立核心范式。理由是 2023 年之后的范式主战场已收敛到自回归、扩散、LLM 三类。

下面分别展开三大范式的机制、代表方法、优势与局限。

### 1.4.4.1　自回归生成（Autoregressive Generation）

**核心机制**。自回归范式把每个物品离散化为一段 token 序列（典型实现是"语义 ID"，Semantic ID），然后用 Transformer 解码器自回归地一次预测一个 token，直到生成出完整的物品标识。形式上它就是公式 (1.8a)。这里的关键是 token 的设计——物品如何从一个连续向量被压缩为可供模型自回归生成的离散 token 序列，是第 2 章的核心主题；本节读者只需要建立一个直觉：可以把语义 ID 类比为图书馆给每本书分配的索书号——它由若干段编码组成，前缀编码相同表示主题相近，模型在生成下一段编码时实质上是在做"按主题逐步定位"。

**代表方法**。

1. **P5（2022 年，[REF-011]）**——RecSys 2022 论文，全称 Pretrain, Personalized Prompt, and Predict Paradigm。P5 第一次系统性地把推荐表达为自然语言生成任务，自回归地生成物品文本，兼跨自回归范式与下文的 LLM 端到端范式。更详细的机制在 §1.3.5 已展开。
2. **TIGER（2023 年，[REF-009]）**——NeurIPS 2023 论文，论文标题为 "Recommender Systems with Generative Retrieval"，来自 Google DeepMind 团队。TIGER 的两点贡献从此被反复引用：（i）用 RQ-VAE（Residual-Quantized Variational Autoencoder）把每个物品编码为一段层次化离散 token——即语义 ID；（ii）用 T5 风格的 Encoder-Decoder Transformer 自回归地解码出物品的语义 ID 序列。它是把"生成式召回"以严义形式系统性跑通的代表性工作——动作空间不再是召回模块给出的候选集，而是语义 ID 词表的笛卡儿积，与全物品库等价。
3. **OneRec（2025 年，[REF-018]）**——快手公开发布的端到端生成式推荐系统，把整个推荐流水线（召回 + 排序）替换为一个 Session-wise 自回归生成模型，并在大规模在线流量上进行了对照实验。OneRec 是自回归范式从学术 Demo 到工业级落地的代表案例，工程细节将在第 4 章展开。

**优势**。自回归范式的吸引力主要在三点——离散语义 ID 天然支持物品冷启动（新物品只要能被分词器分配出语义 ID 即可被模型生成，不依赖历史共现）；端到端单阶段消除了传统级联的目标割裂与误差累积；token 化之后的物品标识天然适配预训练 LLM 的解码骨架，可无缝继承语言模型的预训练知识。

**局限**。代价集中在三处——逐 token 解码导致推理延迟随 token 数线性增长，工业百毫秒约束下需要并行采样、激进剪枝、缓存复用等工程支撑；语义 ID 的分词器与下游推荐目标的联合优化仍是开放问题（详见第 2 章）；left-to-right 单向解码会使整段语义 ID 的"前缀偏置"压制后段 token 的多样性，2025 年的 DiffGRM 等工作专门指出这是"intra-item 一致性"难题。

### 1.4.4.2　扩散生成（Diffusion-based Generation）

**核心机制**。扩散范式借鉴 DDPM/DDIM 在图像生成中的去噪扩散框架——前向过程把目标（用户偏好向量、物品向量、或离散 token 序列）逐步加噪到接近纯噪声，逆向过程由模型一步步去噪并恢复目标，对应公式 (1.8b)。在推荐场景，去噪后的目标可以是用户对全物品的偏好分布、用户的下一交互向量、或一段离散 token 序列（Masked Diffusion）。

**代表方法**。

1. **DiffRec（2023 年，[REF-022]）**——SIGIR 2023 论文，对用户—物品交互向量做加噪—去噪。直观上它把"协同过滤矩阵补全"重新表述为"对用户偏好向量的去噪生成"，从而把生成式建模引入推荐评分预测。
2. **DiffuRec（2023 年，[REF-023]）**——序列推荐视角的扩散生成，建模用户偏好的不确定性分布，本书将其在第 5 章详细展开。
3. **离散扩散 / Masked Diffusion 工作**——2025 年前后开始把扩散过程搬到 token 空间，用并行采样替代逐 token 自回归解码，被视为"双向生成"对自回归"单向生成"的范式补充。本书第 5 章给出代表工作梳理。

**优势**。扩散范式的核心价值是**双向建模**与**不确定性表达**——前者帮助克服自回归的前缀偏置，后者让模型可原生表达"用户在多个偏好之间的概率分布"，在多兴趣推荐与探索性推荐场景中具有结构性吸引力。此外，扩散过程在采样维度上原生支持并行，相比自回归在长序列推理上的延迟劣势具有反向优势。

**局限**。扩散范式仍处于工业落地早期——多步去噪带来的总采样成本目前高于单次自回归解码（即使经 DDIM 加速后也不占绝对优势）；扩散过程与离散语义 ID 的耦合方式仍是开放问题；公开报告的大规模在线对照实验稀少，方法收敛性与工程化路径仍在探索之中。

### 1.4.4.3　LLM 端到端推荐（LLM-based End-to-End Generation）

**核心机制**。LLM 端到端范式利用预训练大语言模型（GPT 系列、LLaMA 系列等）的开放世界知识，把用户历史与推荐指令拼接为提示词（Prompt），由 LLM 自回归地生成自然语言形式的推荐结果（物品标题、物品描述或多物品列表）。形式上它仍是公式 (1.8a)，但与 §1.4.4.1 自回归范式存在两点关键差异——token 词表是自然语言词表而非专门设计的物品 ID 词表；模型主体是预训练 LLM，参数中包含的开放世界知识远超在推荐数据上从零训练的模型。

**代表方法**。

1. **P5（2022 年，[REF-011]）**——P5 同时落在自回归与 LLM 端到端两类范式的交集上。从"使用 T5 预训练语言模型 + 自然语言任务"角度看，它是 LLM 端到端范式最早的实证。
2. **BIGRec [REF-029] / InstructRec [REF-030] / RLMRec [REF-031]（2023—2024 年）**——这一组工作通过指令微调与对齐训练，让 LLM 在推荐任务上更可控地生成物品。其中 BIGRec / InstructRec 重点解决"物品幻觉"——通过限制 LLM 输出在真实物品库内（约束解码或事后映射）；RLMRec 通过让 LLM 生成语义表征再蒸馏到轻量推荐模型，把 LLM 的开放知识平移到工业可服务的小模型上。这些工作的细节在第 6 章统一展开。

**优势**。LLM 端到端范式独有三项**结构性优势**——其一，开放世界知识让推荐系统天然具备处理 zero-shot 与跨域场景的能力；其二，自然语言输出原生支持可解释推荐，模型可在生成物品的同时给出推荐理由；其三，对话交互体验自然，与对话式、搜索式推荐场景天然契合。

**局限**。其代价同样显著——其一，模型规模带来的推理延迟与单次推理成本远高于专门设计的小模型，工业在线服务通常需要量化、蒸馏、推测解码（Speculative Decoding）等组合手段（详见第 9 章）；其二，物品接地（Grounding）问题——LLM 可能生成不存在的物品名（即§1.3.6 提到的物品幻觉），需要约束解码或后置物品库匹配兜底；其三，训练数据需要精心构造的指令模板与负样本，泛化性强依赖提示工程的质量。

## 1.4.5　范式横向对比与全书路线图

把 §1.4.4 三类范式压在一张表里横向比较，可以让读者建立后续章节的"地图"。

**表 1-5　生成式推荐三大范式的六维对比**

| 维度 | 自回归生成 | 扩散生成 | LLM 端到端 |
|---|---|---|---|
| 核心机制 | 物品 token 化 + 自回归解码 | 加噪—去噪过程 | 预训练 LLM + 提示生成 |
| 代表方法（年份） | TIGER（2023）、OneRec（2025） | DiffRec（2023）、DiffuRec（2023） | P5（2022）、BIGRec / InstructRec（2023—2024） |
| 推理延迟 | 中—高（与序列长度成正比） | 中—高（多步采样，可加速） | 高（受 LLM 规模主导） |
| 冷启动能力 | 强（语义 ID 泛化新物品） | 中（依赖交互数据去噪） | 强（开放世界知识泛化） |
| 可解释性 | 弱—中（语义 ID 可追溯但不直观） | 弱（去噪过程不可解释） | 强（自然语言推荐理由） |
| 工业落地难度 | 中（已有公开案例如 OneRec） | 高（公开案例稀少） | 高（成本与幻觉双重约束） |

把表 1-5 与定义 1.1 对照来看，三大范式的**共同内核**就是公式 (1.8) 所表达的"条件生成"思想——它们都把推荐问题重表述为"在给定上下文下、对一个高概率合法输出做生成"，差别只在 $P_{\theta}$ 的参数化方式与 $\mathcal{Y}$ 的具体定义。三类范式同时面临一组共性挑战——生成质量与候选覆盖度的权衡、在线时延约束、训练数据与对齐策略（RLHF / DPO 详见第 7 章）。

## 1.4.6　本节小结与最新进展

**本节核心结论**。本节给出了贯穿全书的三个概念性结论：（1）严义定义——生成式推荐是"直接生成推荐物品或推荐相关内容、无需对每个候选物品逐一打分"的推荐范式（定义 1.1，[REF-007]），其最简检验是判据 1.1；（2）统一形式化——所有生成式推荐方法都可装进公式 (1.8) 的条件生成框架，三大范式的差异只在对 $P_{\theta}$ 的参数化方式与合法输出空间 $\mathcal{Y}$ 的具体定义；（3）三范式分类——按生成机制划分，本书把生成式推荐切分为自回归生成（代表：TIGER、OneRec）、扩散生成（代表：DiffRec、DiffuRec）、LLM 端到端（代表：P5、BIGRec / InstructRec）三类，对应后续第 2—6 章的主轴。

**最新进展（2024—2026）**。三份代表性综述构成本节"分类框架"的学术坐标系——[REF-007]（2023）首次给出严义定义，奠定"生成式 vs 判别式"的范式分界；[REF-070]（KDD 2024 Tutorial）从生成模型谱系视角为三范式分类提供横向佐证；[REF-006]（2025）则用 Data / Model / Task 三维框架把这一分类与最新方法图谱整合到一起。从工业侧看，OneRec [REF-018]（2025）是自回归范式工业级落地的公开里程碑；扩散范式与 LLM 端到端范式的工业级公开案例仍在累积之中——这一节奏差也映射在本书各范式章节的篇幅与案例分布上。

**与 §1.5 的衔接**。有了本节给出的定义（1.1）、判据（1.1）、统一形式化（1.8）与三大范式分类，读者已获得进入第 2—10 章的概念装备。§1.5「全书路线图与阅读指南」将顺着 §1.4.5 的章节路线图进一步细化——按读者背景给出三条阅读路径。从本节起，本书叙事正式从"什么是生成式推荐"切换到"生成式推荐如何按章节展开"。
