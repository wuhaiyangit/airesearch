# 1.2 判别式与生成式的本质差异：打分 vs. 生成、候选池 vs. 开放词表

## 1.2.1 引入：为什么要在第一章就做这组对比

§1.1 用一条时间轴把推荐系统的演进切成四段，并给出了本书使用的"生成式推荐"工作定义。紧接着读者最自然会问的问题是：**如果只保留一句话来区分"判别式"和"生成式"，应该怎么说？**这句话本身并不好写——它必须既要精确到数学建模层面经得起推敲，又要足够具体以免流于"新 vs. 旧""简单 vs. 先进"这类廉价对立。本节就专门回答这个问题。

本节的写作原则是"就事论事"：生成式范式并不意味着判别式范式"过时"。到 2026 年初，工业界的主流仍是"生成式召回 + 判别式排序"的混合架构 [REF-112]，判别式模型在 CTR/CVR 精排、延迟敏感场景中仍然无可替代。但正因如此，才需要把两种范式的差异摆到同一张桌子上对照，看清各自擅长什么、付出什么代价。本节从**概率建模**、**推理流程**、**输出空间**三个层面依次展开，最后落到**混合架构**这一工业现实，给出一张八维对比表，作为后续各章反复引用的基准。

## 1.2.2 概率建模层面的差异：学边界，还是学分布

从概率角度看，判别式与生成式的分野其实并不新鲜——机器学习教材里早就讲过。把它挪到推荐语境下，对应关系如下。

**判别式推荐**直接建模条件概率 $p(y \mid x)$：给定 $x=(\text{用户特征}, \text{候选物品特征})$，预测标签 $y$（点击/不点击、喜欢/不喜欢）。模型只关心**决策边界**——在特征空间里找到一张超平面，把正负样本分开——而不试图理解数据是怎么生成的。代表目标函数是逐对比较正负样本的 BPR loss：

$$
\mathcal{L}_{\mathrm{BPR}} = -\sum_{(u, i^{+}, i^{-})} \log \sigma \bigl( s_\theta(u, i^{+}) - s_\theta(u, i^{-}) \bigr),
$$

其中 $s_\theta(u, i)$ 是模型对用户 $u$ 与物品 $i$ 的打分函数，$\sigma(\cdot)$ 是 sigmoid。所有 CTR 预估模型、双塔召回、SASRec、BERT4Rec 虽然骨架不同，本质都是在学 $p(y \mid x)$ 或与之等价的打分函数 $s_\theta$。

**生成式推荐**则建模**给定上下文的物品（序列）的生成分布** $p(i_1, i_2, \ldots, i_k \mid u, \text{context})$。典型情形下，这被分解为自回归形式：

$$
p(i_1, i_2, \ldots, i_k \mid u, c) = \prod_{t=1}^{k} p(i_t \mid i_1, \ldots, i_{t-1}, u, c),
$$

训练目标是负对数似然：

$$
\mathcal{L}_{\mathrm{AR}} = -\sum_{t} \log p_\theta(i_t \mid i_{<t}, u, c).
$$

两者最深层的差异在于：判别式模型**不需要理解数据从何而来，只要能判别**；生成式模型则必须学到"数据本身长什么样"，这样才有能力从分布中**采样出新的物品**，而不是从一个给定的候选池里挑。从贝叶斯公式 $p(y \mid x) = p(x \mid y) p(y)/p(x)$ 看，判别式是直接跨过 $p(x \mid y)$ 这一项，生成式则把它作为建模主体。

这一差异会沿着架构、训练目标、输出形态、工程代价这四条轴一路传导下去。后续小节会把这条传导链逐级展开。

## 1.2.3 推理流程：多阶段 Pipeline vs. 端到端生成

概率建模的差异一落到系统层面，最直接的表现就是**推理流程**的根本不同。

**判别式推荐的工业形态**，是经过二十年迭代沉淀下来的多阶段 Pipeline：

```
用户请求 → 召回（百万 → 千）→ 粗排（千 → 百）→ 精排（百 → 十）→ 重排 → 展示
```

每一阶段都在做"从大集合中选出小集合"这件事，但各自有独立的模型、独立的特征体系、独立的目标函数——召回层常用 InfoNCE 或 Sampled Softmax，精排层用 BCE 或 pairwise loss，重排层又换成多样性约束或 MMR。这套架构的好处是**工程边界清晰**、每一层都可独立迭代；代价则是被反复讨论过的**级联误差**和**目标割裂**：

1. **级联误差不可逆**：召回阶段截断后，被过滤掉的物品在后续阶段无论如何也无法被召回回来；精排把打分做得再精细，其输入集合的上限已经由召回阶段决定；
2. **局部最优不等于全局最优**：每一层独立训练到的最优解，拼起来未必是端到端意义上的最优解，离线指标提升常常无法线性传导到线上效果；
3. **特征/模型异构带来运维成本**：不同阶段使用不同特征抽取链路，一个特征变更可能需要在多个模型里同步修改。

**生成式推荐的推理形态**则走另一条路：

```
用户请求 → [统一 Transformer] → 自回归生成 Token 序列 → 约束解码 → 命中合法物品 → 展示
```

整个推荐过程被压缩成"一个模型、一次前向"。TIGER [REF-010] 用 RQ-VAE 把物品量化成层次化 Semantic ID，再让 Transformer 自回归地生成下一物品的 Semantic ID Token 元组；HSTU [REF-030] 把用户行为序列中所有物品当作同质 Token，用单一序列转导模型建模，在 Meta 的工业环境中把参数规模推到了万亿级；OneRec [REF-031] 则直接用 Encoder-Decoder 把"召回—粗排—精排—重排"四阶段级联整体替换为一次自回归解码。

端到端带来的收益是显而易见的：**所有阶段的目标函数被统一为一条自回归似然**，不再有召回与排序之间的目标不一致问题；所有阶段共享同一套参数，**模型规模和算力可以集中扩展**。OneRec 技术报告给出的一组工业数据提供了这一收益的注脚：整体计算 FLOPs 较传统 Pipeline 提升约 10 倍，而整体运营成本（OpEx）下降到原方案的约 10.6%，在快手与快手极速版分别承载约 25% 的线上 QPS，停留时长分别取得约 0.54% 与 1.24% 的提升，并带动 7 日生命周期指标的显著增长 [REF-031]。

> **图 1.2.1（拟绘）**：判别式多阶段 Pipeline vs. 生成式端到端推理流程对比。建议绘制为左右双栏流程图：左栏画出"召回—粗排—精排—重排—展示"五个串联方框，每个方框用不同颜色表示不同的模型与目标函数；右栏画一个横跨全宽的"统一 Transformer"大方框，其上方标注"自回归生成 / 约束解码"，下方直接连到"展示"。两栏下方各写一行注脚，左栏写"多模型、多目标、级联误差"，右栏写"单模型、单目标、端到端优化"。配色参考 [REF-001] 综述 Figure 1 的三色体系，并自行重绘避免复用第三方图素。

然而端到端并非没有代价。自回归解码是串行的——第 $t$ 步必须等第 $t-1$ 步的 Token 确定后才能开始——这在大规模场景下会带来明显的延迟压力；多阶段 Pipeline 则天然并行，每一层都可以横向扩展。更重要的是，受限解码（constrained decoding）要求生成出的 Token 序列必须落在合法物品的集合内，这本身需要额外的前缀索引（trie）或码本约束，并非零成本。HSTU 给出的回应是用 M-FALCON 做推理加速，并通过专门为推荐设计的序列转导架构降低单步计算量 [REF-030]；OneRec 则通过训练/推理 MFU 的工程优化（报告值分别约为 23.7% 和 28.8%）接近 LLM 社区水平的利用率 [REF-031]。可以预见，在推理优化成熟之前，判别式 Pipeline 与生成式端到端会长期共存。

## 1.2.4 输出空间：封闭候选池 vs. 开放词表

第三个层面的差异是**输出空间**。这个问题看似细节，实际上直接决定了两种范式在**冷启动**和**新物品覆盖**上的天然能力上限。

判别式推荐的输出是**分值**——一个落在 $[0,1]$ 或实数轴上的标量——被作用到一个**显式给定的候选集** $\mathcal{C}$ 上。这意味着：

- 候选集必须提前准备，通常由召回层产出，大小在 $10^2$ 到 $10^3$ 量级；
- 任何不在 $\mathcal{C}$ 中的物品，无论多么匹配用户兴趣，都**不可能被推荐**；
- 物品的表示是**原子 ID**（或 ID + 内容特征的拼接），新物品在没有任何交互记录前，其 ID embedding 没有被训练过，属于真正意义上的冷启动。

生成式推荐的输出则是一个 **Token 序列**：可以是自然语言（P5 [REF-040]、M6-Rec [REF-041] 把物品表示为文本描述），也可以是 Semantic ID（TIGER [REF-010]、OneRec [REF-031] 把物品量化为 RQ-VAE/VQ-VAE 产出的离散 codeword 元组）。词表是**有限的，但不是物品的枚举**——它是物品被分解后的"子结构"的枚举。这带来两个结构性优势：

1. **输出空间天然开放**。模型理论上能生成任何词表内 Token 的组合，只要解码过程用前缀约束或语义检索对齐到合法物品，就能覆盖所有**表示得出的**物品——包括那些在训练时从未见过的新物品。TIGER 在 Amazon 数据集上报告了对冷启动物品的语义外推能力 [REF-010]。
2. **冷启动物品不再需要从零学起**。新物品只要有内容特征（标题、图像、属性），就可以被量化为 Semantic ID 送进同一个模型；它与老物品共享 RQ-VAE 的码本，因此在模型看来"长得像老物品的一部分"，天然可泛化。

值得单独一提的是 BIGRec [REF-111]。它把"开放词表"这件事做得更彻底：Step 1 让 LLM 直接生成物品的**自由文本描述**（不受任何物品库约束，相当于把词表扩到整个语言空间）；Step 2 再用检索层把生成文本对齐到实际物品库中的最近邻物品。这种"**两步接地（Bi-step Grounding）**"思路明确回答了一个潜在反问："生成式推荐的候选池到底是真没有，还是只是隐式存在？"——在 TIGER 这类工作中候选池隐式存在于词表约束里，而在 BIGRec 中候选池以显式的检索对齐方式出现。BIGRec 论文报告了该范式在 few-shot 场景与跨领域泛化上的表现，并在分析中指出：由于 LLM 的语义先验很强，吸收协同过滤类统计信号的能力反而有限，随训练样本增加的边际收益较小 [REF-111]——这一观察本身，就是"生成式并非万能"的一个具体证据。

**核心公式三段式**（判别式、生成式、偏好对齐）汇总见 §1.2.2 与 §1.2.6；关于 DPO 在推荐中的完整形式，本书第 8 章会专门展开，此处仅指出它是生成式范式得以"按偏好排序"的关键拼图，而非在候选池中打分。

基于以上三个层面的分析，可以把两种范式的差异汇总为下表。表中每一行都是后续章节反复引用的基准，读者可以把这张表看作全书的"坐标底图"。

**表 1.2.1：判别式推荐 vs. 生成式推荐的 8 维核心对比**

| 对比维度 | 判别式推荐 | 生成式推荐 |
|---|---|---|
| 建模目标 | $p(y \mid x)$：学决策边界 | $p(i \mid \text{context})$：学生成分布 |
| 输出形式 | 相关性分数（标量） | Token 序列（Semantic ID 或文本） |
| 候选池 | 显式、封闭，由召回层产出 | 隐式存在于词表中，或由二次检索对齐 |
| 训练目标 | BCE / BPR / InfoNCE | 自回归 NLL / ELBO（扩散） |
| 负样本依赖 | 强，采样分布对效果敏感 | 弱，不显式依赖负样本 |
| 推理方式 | 多阶段并行打分，延迟低 | 自回归串行，延迟较高 |
| 冷启动能力 | 弱，依赖历史交互与 ID embedding | 强，可借 Semantic ID 或文本做语义泛化 |
| 工业现状 | 精排层主流、成熟稳定 | 召回端起步，端到端在少数头部平台验证 [REF-030] [REF-031] |

需要强调的是，这张表列出的是**两端的典型状态**，而不是非此即彼的二分法。现实中的很多方法（例如把 LLM 嵌入到传统排序层中作为特征抽取器）会落在这条连续谱的中间地带；第 6 章讨论 LLM4Rec 时会回到这一点。

## 1.2.5 混合架构：工业现实与未来走向

把前三小节的分析合起来，可以得到一个比"生成式取代判别式"复杂得多的结论：两种范式在**不同阶段**和**不同场景**下各有所长，真正在工业界大规模铺开的，是它们的**混合形态**。

最典型的混合形态是**生成式召回 + 判别式排序**。召回层对"覆盖率"和"冷启动"敏感，恰好契合生成式"开放词表 + 语义泛化"的优势；精排层对"低延迟"和"精准概率估计"敏感，则继续由判别式 CTR/CVR 模型担纲。小红书 NoteLLM [REF-060][REF-112] 就是此类架构的公开案例之一：LLM 被用作 I2I 召回侧的语义检索器，精排仍然是传统深度模型。Netflix 的 LLM-inspired foundation model 也沿类似思路，把 LLM 的能力注入到推荐基础设施中，而非全链路替换 [REF-004]。IEEE Access 2025 的综述把当前 LLM4Rec 系统划分为"判别式 / 生成式 / 混合"三大类并进一步细分，其中"混合类"至 2025 年已成为公开文献中出现频率最高的工业落地形态 [REF-112]。

另一类在 2024—2025 年受到密集关注的尝试，是**端到端生成式替代全链路**。OneRec [REF-031] 是公开报告中走得最远的代表：它用同一个 Encoder-Decoder 模型承担原先由召回、粗排、精排、重排四个阶段完成的工作，在快手主站承担约 1/4 的 QPS，并在业务指标上取得正向 [REF-031]。但这类方案对训练/推理基础设施的要求很高——OneRec 报告中反复强调的"10 倍 FLOPs、MFU 接近 LLM 社区"这组数字，同时也是其工程门槛的说明。对多数中小规模业务而言，混合架构仍然是更务实的起点。

生成式推荐与强化学习/偏好对齐的结合，是推动端到端方案迈向"可按业务目标调优"的关键一步。OneRec 在摘要中特别指出，端到端生成式框架使**强化学习**这类此前在推荐系统中难以规模化应用的技术重新成为可能 [REF-031]。其具体做法——用 SFT 得到基线策略、再用 Iterative Preference Alignment（IPA，底层基于 DPO 类方法）做偏好对齐迭代——会在第 8 章详细展开。此处只需要给出它的最小公式形式以便读者建立直觉：

$$
\mathcal{L}_{\mathrm{DPO}} = - \log \sigma \!\left( \beta \log \frac{\pi_\theta(y^{+} \mid x)}{\pi_{\mathrm{ref}}(y^{+} \mid x)} - \beta \log \frac{\pi_\theta(y^{-} \mid x)}{\pi_{\mathrm{ref}}(y^{-} \mid x)} \right),
$$

其中 $y^{+}$、$y^{-}$ 分别是人类或规则给出的优、劣序列，$\pi_\mathrm{ref}$ 是参考策略。DPO 把"让 $y^{+}$ 比 $y^{-}$ 更可能"这件事直接写进损失，避免了显式训练奖励模型；对生成式推荐来说，它是从"最大似然复现历史"跨到"按偏好生成未来"的关键拼图。

## 1.2.6 小结与本节要点

本节从概率建模、推理流程、输出空间三个层面比较了判别式推荐与生成式推荐，最后落到工业混合架构这一现实。要记住的要点是：

1. **建模目标不同**：判别式学 $p(y \mid x)$，生成式学 $p(i \mid \text{context})$；前者刻画决策边界，后者刻画生成分布。
2. **推理流程不同**：判别式是多阶段并行 Pipeline，存在级联误差与目标割裂；生成式是端到端自回归，统一目标但代价是串行延迟与约束解码成本。
3. **输出空间不同**：判别式输出分值并作用于封闭候选池；生成式输出 Token 序列，候选池隐式存在于词表中（TIGER 路线）或由二次检索对齐产出（BIGRec 路线）。
4. **工业现状是混合为主**：生成式召回 + 判别式排序是当前最普遍的落地形态；端到端替代（如 OneRec）在少数头部平台得到验证，但对基础设施要求高。
5. **范式不是互斥**：表 1.2.1 列出的 8 个维度构成一条连续谱；很多真实系统会落在谱的中间，而不是两端。后续章节中遇到任何一个新方法，都可以把它放回这 8 个维度先做定位。
6. **生成式并非在所有场景全面胜出**：BIGRec 的实验即已揭示，LLM 的语义先验虽强，但吸收协同过滤类统计信号的能力反而有限 [REF-111]；这是生成式范式需要与判别式范式继续互补的结构性原因之一，也是全书第 8 章讨论"对齐 / 强化学习"时必须回到的底层事实。
