# 1.3　生成式 AI 浪潮的冲击

## 1.3.1　本节定位：从"内部修补"到"外部冲击"

§1.2 在结尾提出了一个判断——深度学习把推荐系统的每一个组件都压榨到极限之后，剩下的三条天花板（精排序列长度上限、召回语义鸿沟、ID-based 序列建模）都不再是工程问题，而是范式问题。要打破范式问题，仅靠推荐领域内部的工程优化已经不够，真正的契机来自一个外部学科：自然语言处理（Natural Language Processing，NLP）领域在 2020 年之后所经历的"大规模语言模型革命"。本节的任务，就是从推荐系统的视角解释这场外部革命的**机制是什么、推荐领域为什么应该被它撼动、以及这种撼动按怎样的阶段层层渗透到推荐管道之中**。

需要事先澄清的是，本节并不打算介绍 GPT-3、ChatGPT 或 GPT-4 本身——视角始终锚定在"推荐领域"：每当谈到一个 LLM 能力，下一句一定会回到"它对推荐意味着什么"。在这个意义上，§1.3 与 §1.2 形成历史呼应——前者解释深度学习如何补救传统级联架构、后者解释生成式 AI 如何从外部冲击整套架构，§1.4 将在两节铺垫之上正式回答"什么是生成式推荐"。

## 1.3.2　历史脉络：LLM 革命的三个关键节点与推荐界的反应时差

把 2017 年 Transformer 论文 [REF-005] 视为这条故事线的零点（NLP 与推荐共享的架构起点），LLM 时代真正的"奠基—破壁—爆发"三个节点可以这样划分：

- **2020 — 涌现能力的奠基**：GPT-3 [REF-065] 把语言模型参数量推到 1750 亿，第一次系统性地展示出"少样本学习（Few-Shot Learning）"——不更新参数，仅靠提示词中的少量示例，模型即可在翻译、问答、推理等多类任务上接近甚至超越任务特定微调的基线。该论文被 NeurIPS 2020 评为最佳论文（Best Paper），标志着"扩规模即获得新能力"这一观察被学界正式接受。
- **2022 — 指令遵循与任务统一**：InstructGPT [REF-033] 用基于人类反馈的强化学习（Reinforcement Learning from Human Feedback，RLHF）使 LLM 学会按指令完成任务；与此同时，P5 [REF-011] 在 RecSys 2022 上首次把多类推荐任务全部翻译成自然语言序列，统一在一个文本到文本（Text-to-Text）模型中训练。前者让 LLM "听得懂"用户指令，后者让推荐研究者第一次看到"推荐任务可以是语言任务"的实证。
- **2022 年底至今 — 推荐界的全面反应**：2022 年 11 月 ChatGPT 公开发布之后，推荐研究界几乎在半年内涌出了第一批系统性的 LLM 推荐评估工作，其中 Dai 等人（2023 年）的 ChatGPT 推荐能力评估 [REF-069] 是最早一批之一。2024 年开始，How LLMs Benefit RS [REF-066]、A Survey of Generative Search and Recommendation [REF-067]、Towards Next-Gen LLM-based RS [REF-068] 等综述陆续问世，标志着学界从"分散尝试"进入"系统总结"。2025 年快手 OneRec [REF-018] 等工业级端到端生成推荐系统上线，则把这场冲击从论文带到了真实业务流量上。

值得专门指出的是，推荐界对 LLM 的反应存在明显**时差**——GPT-3 发表于 2020 年，主流推荐顶会 LLM 论文的爆发要等到 2023 年的 RecSys / SIGIR。这一约一年半的时差并非偶然：推荐与 NLP 在评估指标、数据规模、任务定义上长期存在结构性差异，而 LLM 对推荐的真正价值不在"语言生成"本身，而在它对推荐范式的根本扰动。理解这种"扰动机制"，需要从能力侧切入到管道侧。

## 1.3.3　冲击机制：LLM 给推荐带来的四重能力革命

为了把"LLM 革命对推荐有什么用"解释清楚，可以将其拆解为四条相互独立、又彼此呼应的能力路径。每一条都精准对应 §1.2 揭示的某条天花板，这种对应关系本身就是本节叙事的内核。

**路径一：开放世界知识（Open-world Knowledge）→ 化解语义鸿沟。** 传统推荐的物品表示是随机初始化的 ID Embedding（§1.2 公式 (1.5)），它的全部语义都来源于行为共现。但行为稀疏区（冷启动、长尾、跨域）天然没有共现信号，因此向量空间在这些区域几何上是"空"的。LLM 在万亿规模文本上预训练，其参数中沉淀了关于物品的标题、品类、属性、用法、典型用户群、文化关联的开放世界知识。综述 [REF-066] 在引言中明确指出，常规推荐模型（Conventional Recommendation Model，CRM）"缺乏开放世界知识，难以理解用户深层偏好与动机"，而 LLM 的这一特性恰好是 CRM 的"反向短板"。这条路径的物理含义是：LLM 把"召回阶段语义鸿沟"从一个工程难题变成一个知识迁移问题。

**路径二：少样本泛化（Few-Shot Generalization）→ 化解冷启动与跨域瓶颈。** GPT-3 [REF-065] 的核心观察是：当模型参数量达到一定规模后，仅靠提示词中的少量示例（in-context learning）即可让模型完成新任务，无需任何梯度更新。可以用一个直观类比来理解这一能力——传统监督学习像"每教一门课都要重新培养一个老师"，in-context learning 则像"一个博学的人看几页讲义就能上岗代课"。推荐场景里，每个新平台、新品类、新用户群在传统范式下都需要重新积累足够的行为数据；少样本泛化让"复用老平台的知识到新场景"第一次具备了模型层的支撑。

**路径三：任务统一（Task Unification）→ 缓解级联架构的目标割裂。** §1.1 揭示过，传统推荐管道中召回、粗排、精排、重排各自有独立模型与目标，缺乏联合优化。P5 [REF-011] 给出的处理方式是：把所有推荐数据——用户—物品交互、用户描述、物品元数据、评论——统一转换成自然语言序列，把不同推荐任务表达为同一个 Text-to-Text 训练目标。在这一思路下，"召回与排序的目标割裂"在原理上不再存在——一个模型用一种损失同时完成多类任务。

**路径四：生成范式（Generative Paradigm）→ 直接突破"先候选再打分"的结构性约束。** 这条路径是上述三条的合流，也是本书后续所有章节真正要展开的主题。综述 [REF-067] 把信息检索（含搜索与推荐）的范式划分为"机器学习—深度学习—生成式"三个阶段，并以原文摘要中"superintelligent generative large language models have sparked a new paradigm"作为对第三阶段定性的核心依据。生成式范式与判别式范式的根本差别在于：判别式必须先有候选集才能打分，候选集的天花板就是系统天花板（这一观察在 §1.1 的召回综述讨论里已经成为本书的"承重论断"之一）；而生成式直接从模型概率分布中采样物品，理论上动作空间是整个物品库。可以把这一差别类比为"翻字典找词"与"直接说出一个词"——前者受字典覆盖度限制，后者受语言模型本身的能力限制。

将四条路径放在一起回看，§1.2 的三条天花板与四条路径形成几乎一一对应的关系：召回语义鸿沟对应路径一与路径四；冷启动与跨域瓶颈对应路径二；级联目标割裂对应路径三；序列建模的 ID-based 表示局限则需要路径一与路径四联合起作用——这也是为什么"语义 ID + 自回归生成"在第 2、第 3 章会被作为生成式推荐技术核心反复出现。需要在这里点出的是：**这一问题的根本解法要等到语义 ID 体系的建立（第 2 章）才真正成熟**，本节只负责指出方向，不展开技术细节。

## 1.3.4　三阶段演进：从 LLM as Feature 到 LLM as Generator

四条能力路径的工程落地不是一夜之间完成的，而是按"逐步替换"的方式渗透进推荐管道。综述 [REF-066] 在 WHERE × HOW 双维度框架中（其 WHERE 维度覆盖特征工程、特征编码器、打分与排序、用户交互、管道控制器五个推荐阶段；HOW 维度区分是否调优 LLM、是否仍依赖常规推荐模型）回答了"LLM 在哪一层进入推荐管道"的问题；综述 [REF-068] 则进一步提出"第一代 LLM 辅助推荐 → 第二代 LLM 原生推荐"的两代演进框架。把这两份综述的视角汇合，可以把 LLM × 推荐的演进概括为三阶段时间线，如图 1-5 所示。

**阶段一：探索期（2020 – 2022），LLM as Feature。** 这个阶段最直接的做法是：保留传统推荐管道，把 LLM 当成一个"加粗的语义特征提取器"。例如把物品标题、描述、评论拼接后输入 LLM，取最后一层隐状态作为该物品的语义嵌入（Semantic Embedding），再与原有的 ID Embedding 拼接送入排序模型。该思路的优点是**改造成本低**——CRM 的训练流程几乎不动；缺点也很明显——LLM 仅承担了"更好的 BERT"的角色，其推理能力、生成能力、指令遵循能力全部被浪费。以综述 [REF-066] 的 WHERE 维度为例，本阶段的工作主要落在 feature engineering 与 feature encoder 两层。

**阶段二：融合期（2022 – 2023），LLM as Scorer / Ranker。** 这个阶段开始让 LLM 直接参与打分或排序决策。代表方向之一是把候选物品列成 Prompt，让 LLM 输出"相关性评分"或"重排顺序"。Dai 等人（2023 年）针对 ChatGPT 在多个推荐数据集上系统评估了 point-wise、pair-wise、list-wise 三种排序策略，结论是 ChatGPT 在三种策略下都优于其他通用 LLM 基线，其中 list-wise 在性能与成本之间取得最佳折衷 [REF-069]。该论文同时指出，ChatGPT 在冷启动场景与可解释推荐两方面"展示出潜力"。这是 LLM 第一次以"打分员"身份直接进入推荐决策流程，但它仍然依赖外部召回模块给出候选集——它没有改变"先候选后打分"的判别式骨架。该阶段对应 [REF-066] WHERE 维度的 scoring/ranking function 与 user interaction 两层。

**阶段三：生成期（2023 – 2025+），LLM as Generator。** 这个阶段才是真正意义上的"生成式推荐"——把推荐结果当作模型直接生成的内容（自回归地生成物品标识或物品序列），从而摆脱候选集前置约束。综述 [REF-067] 将这一阶段定性为信息检索的"第三次范式转变"，[REF-068] 把它命名为"第二代（原生）LLM 推荐"。工业实践方面，2025 年快手 OneRec [REF-018] 用端到端生成模型替代多阶段级联，公开报告了 watch-time 等业务核心指标的显著提升（其工程细节将在第 4 章展开）。学术侧 P5 [REF-011] 早在 2022 年就已经验证了"推荐任务可以表示为语言生成"，但从"语言生成可行"到"工业级端到端生成"中间还有 ID 表达、效率、对齐三道关键技术鸿沟需要跨越——这正是后续第 2、第 4、第 7 章的主线。

把三阶段时间线拉直来看可以得到一个有用的判断——**LLM 的能力没有一次性涌入推荐管道，而是按"特征→打分→生成"自浅入深逐层渗透**。这种渗透不是工程师的偏好，而是被工业延迟约束、模型成本、数据安全、与现有系统的兼容性等多重约束共同塑造出来的路径。

## 1.3.5　里程碑解析：P5 为什么是"推荐即语言生成"的第一个证明

在三阶段叙事中，P5 [REF-011] 跨阶段地起到了承上启下的作用——它一脚踏在融合期，一脚伸向生成期。本小节将其作为本章的"高光时刻"重点展开。

**动机层面**，P5 解决的问题与 §1.1 揭示的"目标割裂"高度同构：传统推荐里，评分预测、序列推荐、解释生成、评论生成、直接推荐这些任务各有专门模型，彼此知识无法迁移。P5 论文摘要的第一句即点明这一痛点："不同推荐任务通常需要设计任务特定的架构与训练目标，因此学到的知识与表示难以迁移"——它要解决的恰是 §1.1 的目标割裂问题，但解决路径不在系统侧（多目标融合）而在模型侧（任务统一）。

**模型结构层面**，P5 的全称是 Pretrain, Personalized Prompt, and Predict Paradigm，建立在 T5 文本到文本架构之上。它把所有推荐数据——用户—物品交互、用户描述、物品元数据、评论文本——全部转写为自然语言序列，把不同推荐任务表达为同一组 Prompt 模板。模型训练目标只有一个：以语言建模的负对数似然最小化生成目标文本。可以把它的范式从形式上写作：

$$
P\!\left(y_{1:T}\,\big|\,x\right)\;=\;\prod_{t=1}^{T} P\!\left(y_t\,\big|\,y_{<t},\,x\right). \tag{1.7}
$$

公式 (1.7) 中，$x$ 是任务自然语言描述（含用户上下文与候选物品文本），$y_{1:T}$ 是模型自回归生成的输出 token 序列；每一步 $P(y_t\mid y_{<t}, x)$ 由共享的 Transformer 解码器给出，与 §1.2 公式 (1.6) 的自注意力前向计算同构。该式相比 §1.2 中的"先打分再排序"判别式形式有一个根本变化——推荐结果由"对候选集打分"变为"按概率从词表（在 P5 中是文本词表，在后续语义 ID 工作中是物品标识词表）中逐 token 生成"。这一概率形式将贯穿本书第 3—5 章，是生成式推荐范式与判别式范式的最直观分界。

**训练与推理层面**，P5 在多个推荐基准上以同一组参数完成五大类任务（评分预测、序列推荐、解释生成、评论相关任务、直接推荐），其中部分任务在零样本与少样本设置下达到与单任务专用模型相当的水平。从工程意义上，P5 第一次让"一个模型跑全套推荐流水线"在论文级别成为可能。

**关键结果与历史地位**。P5 是 RecSys 2022 论文，发表于 ChatGPT 公开发布之前，独立得出了"推荐即语言生成"的结论。它给后续工作留下了三个关键遗产：（1）确立 Prompt 模板设计在推荐领域的合法性，使后续大量工作沿用 instruction-style 表达；（2）证明多任务统一在推荐中并非空想，激励了端到端生成式架构（如 OneRec [REF-018]、TIGER 等）的探索；（3）把"LLM 推荐"的工程问题从"用 LLM 做特征"提升到"用 LLM 做架构"。

**局限性**也必须客观点出。P5 的输出受限于已见过的物品文本——当生成阶段产生"训练时未见过的物品名"时即出现幻觉；其文本 ID 不携带行为协同信号，与 ID-based 推荐相比在密集行为场景下表现仍有差距；Seq2Seq 的解码代价在工业百毫秒时延约束下也难以直接支撑。这些局限不是 P5 的失败，而是它"踩出来"的下一程问题——语义 ID 表示（第 2 章）与高效生成（第 4 章）正是为系统性回答这些问题而生。

## 1.3.6　早期实证与共识性挑战：能力边界的客观刻画

只讲优势的章节是不完整的。LLM 进入推荐之初，一批系统性评估工作给出了它在"能做什么、不能做什么"上的早期答案。

Dai 等人（2023 年）评估 ChatGPT 在多领域推荐数据集上的零样本/少样本能力，从 point-wise、pair-wise、list-wise 三个排序策略维度展开 [REF-069]，核心发现可概括为两点：第一，ChatGPT 在三种排序策略下均优于其他通用 LLM 基线，list-wise 在准确率与 API 调用成本之间取得最佳折衷；第二，ChatGPT 在冷启动与可解释推荐场景上"展现出潜力"。同时该评估也明确，传统 CRM 在精确协同过滤任务（需要稠密用户行为记忆）上仍维持优势，LLM 的能力优势集中在文本语义、知识迁移、解释能力等"非传统强项"上。

业界后续工作在 [REF-066] [REF-068] 等综述中反复总结出 LLM 推荐落地的两类共性挑战，本书将之作为后续章节技术解法的"问题起点"：

- **物品幻觉（Item Hallucination）**：当 LLM 直接生成物品名或物品描述作为推荐结果时，可能输出训练语料中存在但当前业务库里不存在的物品（甚至虚构物品）。这在通用对话场景中可被容忍，但在推荐场景中是不可接受的——推荐结果必须是真实库内的可点击/可购买物品。这一问题的根本解法要等到语义 ID 体系的建立（第 2 章）才真正成熟，思路是：用语义 ID 替代自由文本作为生成目标，使生成空间天然约束在物品库内。
- **流行度偏差（Popularity Bias）**：LLM 的训练语料中，热门物品的描述与提及频率远超长尾物品；这种语料分布会被 LLM 继承下来，导致它在推荐时倾向于产出热门候选，从而削弱个性化能力。综述 [REF-066] 将该问题归入 efficiency / effectiveness / ethics 三大挑战中的 effectiveness 维度，[REF-067] 也将其列为生成式信息检索的开放问题之一。该问题的系统化解法在第 7 章「偏好对齐」展开，技术路径包括 RLHF [REF-033]、DPO 系列、以及推荐场景特有的偏置修正。

把这两类挑战与四条能力路径合在一起看，会得到一个有用的视角——LLM 给推荐带来的不是"全是好处"，而是"机会与代价的重新分配"：它把传统推荐解决得相对成熟的协同过滤与稠密行为建模问题暴露在新的风险面前（幻觉、偏差），同时把传统推荐难以解决的语义、跨域、冷启动问题转化成了知识迁移问题。理解这一权衡，是判断后续技术方案"是否真的解决了问题"的基础。

## 1.3.7　范式对照、最新进展与下一节预告

为了把传统推荐、LLM 辅助推荐、生成式推荐三种范式的本质差别一次性摆清楚，表 1-3 给出了五个核心维度上的横向对比。这张表是本节的"答卷"，也是 §1.4 正式定义"生成式推荐"时的必要参照系。

**表 1-3　三种推荐范式的本质对比**

| 维度 | 传统推荐（§1.1—§1.2） | LLM 辅助推荐（§1.3 阶段一—二） | 生成式推荐（§1.3 阶段三 → 全书后续） |
|---|---|---|---|
| 物品表示 | 随机初始化 ID Embedding | LLM 输出的语义 Embedding | 语义 ID token 序列（第 2 章） |
| 推荐范式 | 判别式：候选集打分→排序 | 判别式：LLM 打分或重排 | 生成式：自回归直接生成物品（标识）序列 |
| 候选集需求 | 必需（级联漏斗约束动作空间） | 必需（候选集仍由 CRM 提供） | 理论上不需要（动作空间≈全量物品库） |
| 训练数据 | 行为日志 | 行为日志 + 自然语言（标题/描述/评论） | 行为日志 + 语言/语义监督（含语义 ID 指令） |
| 冷启动能力 | 弱（依赖历史行为共现） | 中（LLM 开放世界知识辅助） | 强（语义泛化 + 少样本生成） |
| 代表工作 | YouTube DNN / DIN / SASRec / SIM | ChatGPT 推荐评估 [REF-069]、各类 LLM 特征/打分工作 | P5 [REF-011]、TIGER（第 3 章）、OneRec [REF-018]（第 4 章） |
| 主要风险 | 语义鸿沟、目标割裂、冷启动 | LLM 推理成本、与 CRM 集成复杂度 | 幻觉、流行度偏差、生成效率 |

**最新进展（2024 — 2026）**。三份综述串起来构成了本节"范式判断"的学术坐标系：[REF-066] 在 ACM TOIS 2024 上完成对 LLM × 推荐 100+ 工作的 WHERE × HOW 双维系统梳理；[REF-067] 在 2024 年 4 月明确将"机器学习—深度学习—生成式"列为搜索与推荐共享经历的三次范式转变；[REF-068] 在 2024 年 10 月提出"第一代 LLM 辅助推荐 → 第二代 LLM 原生推荐"两代演进框架。工业侧，2025 年快手 OneRec [REF-018] 把端到端生成推荐第一次推到大规模在线流量上。把综述与工业落地放在一起看，可以负责任地给出一个判断——2024—2026 年间，"生成式推荐"已经从一个学术假设变成有工业证据支撑的范式选项；后续章节的技术展开，都建立在这一判断之上。

**下一节预告**。经过本节的能力路径梳理与三阶段演进分析，一个核心问题浮出水面：当我们说"生成式推荐"时，到底在指哪一类系统？综述 [REF-007] 在 2023 年 RecSys 上系统回答了"什么是生成式推荐、为什么演进到这个范式、如何实现"三个问题，给出了被学界广泛接受的工作定义；[REF-067] 与 [REF-068] 则进一步在范式光谱上为它划清了与"LLM 辅助推荐"的边界。这些定义与边界的正式厘清，将是 §1.4「生成式推荐的定义与分类框架」的主要内容；§1.4 之后，§1.5 将顺势把生成式推荐切分为"自回归生成、扩散生成、LLM 生成"三类范式。从本节起，本书叙事正式从"为什么需要范式切换"切换到"切换之后是什么"。
