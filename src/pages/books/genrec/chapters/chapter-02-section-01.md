## 2.1.1　从「词表」类比切入：本节解决什么问题

第 1 章末尾留下了一个十分凝练的类比——**语义 ID 之于自回归生成式推荐，相当于自然语言之于大语言模型；它是模型解码的「词表」，决定了模型可以「说出」哪些物品、能否泛化到新物品、能否在物品之间表达层次化的语义关系**。这一类比落到工程层面，几乎所有读者都会立刻追问三个问题：为什么必须要有这样一个「词表」？传统推荐过去十年用得很好的连续 Embedding 不能直接拿来生成吗？以及，如果一定要离散化，这个过程具体要满足哪些设计目标？

本节回答这三个问题。本节是第 2 章的开篇，也是 §1.5 图 1-7 中所标注的全书「窄腰」（the narrow waist）的入口。第 1 章给出的是 *是什么 / 为什么必须出现 / 怎么分类* 的概念地基，第 2 章则进入第一块技术砖石——**物品的离散化表示与语义 ID（Semantic ID）体系**。其中 §2.1 是动机章，专门讲清「为什么要做离散化」；§2.2-§2.6 则是方法章，从 VQ-VAE 到 RQ-VAE、从冻结到联合优化、从纯语义到协同信号注入，逐层把语义 ID 的具体构造方法展开。读者如果暂时不打算精读第 2 章方法层细节，至少要把 §2.1 读完——它是后续自回归式（第 3-4 章）、扩散式（第 5 章）、LLM 端到端（第 6 章）方法在解释「物品 token 从哪里来」时都要回头引用的源点。

为后续讨论先约定一组符号：用 $i \in \mathcal{I}$ 表示物品库中的某一物品，$|\mathcal{I}| = N$ 表示物品总数；用 $\mathbf{e}_i \in \mathbb{R}^d$ 表示物品 $i$ 的连续向量表示；用 $s_u = (i_1, i_2, \dots, i_t)$ 表示用户 $u$ 的历史行为序列；用 $V$ 表示自回归模型的解码词表，$|V|$ 表示词表规模。讨论范围限定在工业级推荐场景——典型的 $N$ 取值在 $10^7\sim 10^{10}$ 量级（如京东的约 40 亿 SKU、淘宝的数十亿商品、YouTube 的数十亿视频候选 [REF-056]），这是后续所有「连续行不行 / 离散怎么压」讨论的物理背景。

## 2.1.2　从连续到离散：自回归生成的本质矛盾

要回答「为什么需要离散化」，必须先回到自回归生成模型的数学本质。无论是 GPT 系列在自然语言上的成功，还是 P5（2022）[REF-011]、TIGER（2023）[REF-009]、OneRec（2025）[REF-018] 等在推荐上的延续，它们都共享同一套生成机制：**给定一个有限的离散词表 $V$，模型在每个解码步上对 $V$ 中所有 token 计算条件概率 $p_\theta(v\mid \cdot)$，再以 softmax 归一化、采样或贪心选择，逐 token 地把目标对象「生成」出来**。这一机制对推荐场景的直接含义是：

$$
p_\theta(i_{t+1} \mid s_u) = \prod_{k=1}^{L} p_\theta\bigl(c_k \mid c_{<k},\, s_u\bigr) \tag{2.1}
$$

其中 $i_{t+1}$ 是要生成的目标物品，$(c_1, c_2, \dots, c_L)$ 是它在某种「物品词表」下的离散 token 序列，$L$ 是序列长度（或称语义 ID 层数），$c_k \in V$。读者在这里只需把握一点直觉——**式 (2.1) 把物品级别的预测拆成了 $L$ 步、每步在 $|V|$ 个 token 上做 softmax 的过程**：每一步的搜索空间都被压缩到 $|V|$ 这个常数，整个序列的组合空间却仍是 $|V|^L$。这种「逐 token 解码 + 组合容量爆炸」是大语言模型能扩展到万亿级语料的核心原因，也是生成式推荐想要复用的工程红利。

这一机制对物品表示提出了几乎是强制性的要求：**目标物品必须能被表达为有限词表上的离散 token 序列**。把这个要求按「连续 / 离散」「有限 / 无限」两个维度展开，立即可以看出连续 Embedding 路线在自回归生成下的三重根本矛盾。

**矛盾一：连续空间不可遍历。** 传统推荐用连续向量 $\mathbf{e}_i$ 表示物品，相似度由内积或余弦距离决定，召回则借助 ANN（Approximate Nearest Neighbor）在 $\mathcal{I}$ 上做近邻查找——这是 §1.2 详细梳理过的「Embedding + ANN」工业范式 [REF-056]。但是，**自回归模型的 softmax 必须作用在一个有限离散集合上**：在 $\mathbb{R}^d$ 这种连续空间上做 softmax 是没有定义的，无法构造合法的概率分布；即便用「在候选池上做内积再归一化」这种近似（这正是双塔召回的做法），也丧失了 token-level 的逐步生成能力——它只能在已知的 $\mathcal{I}$ 内打分，无法「无中生有」地生成尚未训练时见过的物品组合。

**矛盾二：物品级词表规模爆炸。** 退一步，如果把每个物品当作一个独立的 token，让 $V = \mathcal{I}$、$L = 1$，技术上确实能让 (2.1) 式回到一步生成。这正是 P5 [REF-011] 在 2022 年的做法——它把每个物品编码为一个独立的文本 ID（如 `item_3217`），整个推荐过程被「语言化」为 prompt → text 生成。这个做法在学术数据集（万级到百万级物品）上跑通了「物品可以被生成」这一前提，也因此被视为生成式推荐的早期里程碑；但一旦推到工业规模就立刻撞上**词表规模爆炸**的天花板：

$$
|V|_{\text{atomic}} = N,\qquad |V|_{\text{sid}} = K,\quad K^L \geq N \tag{2.2}
$$

式 (2.2) 给出了两种极端的对比——**直接用物品 ID 作 token 的「原子化（atomic）方案」需要 $|V| = N$，工业级 $N \in [10^7, 10^{10}]$ 时，仅词嵌入矩阵就要占用数 TB 显存**；而后面将看到，**语义 ID 方案只需要一个固定大小的码本 $V$（典型 $K = 256\sim 1024$）配合 $L = 3\sim 8$ 层的组合，就足以覆盖 $N \leq K^L$ 的物品空间**。例如取 $K = 256, L = 4$ 即可覆盖 $\approx 4.3\times 10^9$ 个物品，词表规模却仅为 256；取 $K = 1024, L = 3$ 也能覆盖 $\approx 1.07\times 10^9$，词表 1024。读者可以将这种「以小博大」的思路类比为编码论中常见的**多位组合编码**：单位维度容量有限，但 $L$ 个维度通过笛卡尔积把容量推到 $K^L$，正是这种组合放大让自回归生成式推荐的算力开销与 LLM 处于同一个数量级，而不是被物品数量直接拖垮。

**矛盾三：稀疏 ID 缺乏泛化。** 即便先放下词表规模的工程问题，原子化的随机 ID 还有更深一层的语义层面缺陷——**无内涵（no intrinsic meaning）**。`item_3217` 与 `item_3218` 在数学上看仅是两个互斥的整数，模型必须从协同信号里完全凭空学到它们各自的表征；两个物品之间的相似性、层次关系、模态特征都只能间接地通过共现统计逼近。其后果在工业实践中已被反复验证：新物品没有共现历史，对应的 embedding 行就是随机初始化值——这就是著名的**冷启动失效**问题；尾部物品共现稀少，embedding 训练欠拟合——这就是**长尾偏置**问题。两类问题都不是单纯靠加大模型容量能解决的，它们的根源是 ID 空间本身没有承载语义。

把三条矛盾合起来看，结论是清晰的：**自回归生成机制（公式 2.1）+ 工业级物品规模（$N \geq 10^7$）+ 现实的泛化要求 = 必须为物品设计一种新的离散化表示方案**。这种方案要满足「词表规模与物品数量解耦」「token 之间承载语义」「能与自回归解码无缝对接」三重要求；它在文献中的标准名字，就是 *Semantic ID*——语义 ID。

## 2.1.3　传统标识方式的两个对照点：原子 ID 与文本 ID

要把语义 ID 的设计目标说清楚，最有效的方式是把它和两种已被工业 / 学术界用过、也被证明各有局限的方案放在同一坐标系里：**原子 ID（atomic ID）**与**文本 ID（textual ID）**。

**原子 ID（atomic ID）**——把每个物品独立编号为一个整数（如 1, 2, ..., $N$），是过去十年深度学习推荐的事实标准 [REF-056]。优势是简单、唯一、无歧义；劣势在 §2.1.2 已分析：词表规模 $= N$、token 之间无语义、冷启动失效、显存爆炸。原子 ID 在传统的「Embedding + ANN」范式下足够好用，因为模型只需给每个物品学一个稠密向量并在向量空间里做近邻查找；一旦切到自回归生成，它立刻成为整条流水线的瓶颈。

**文本 ID（textual ID）**——P5 [REF-011] 与后续一批 LLM 推荐工作普遍采用，做法是把物品编号编码为类似 `"item_3217"` 的文本字符串、再借由 LLM 自带的 BPE 词表分解为若干 token。语义性比原子 ID 更强一点（前缀让模型知道这是一个「物品类」对象、数字按 BPE 子词级别有统计相似性），但局限同样明显：**第一**，语义来源是数字字面序，「3217」与「3218」相邻没有任何业务含义；**第二**，BPE 词表对长尾数字的覆盖不均，同样位数的物品 ID 经常被切成不同长度的 token 序列，引入难以控制的方差；**第三**，序列长度不可控——一个 8 位数字 ID 经 BPE 后通常占 3-5 个 token，与下面要讲的「定长语义 ID」相比，在 KV 缓存与解码延迟上明显劣势。文本 ID 在中小规模学术数据集上跑通了概念验证，但在工业级 $N$ 与延迟约束下不再具备主导地位——这正是 §1.3 把 P5 视为里程碑、却也明确指出其局限的原因。

把两种方案与本节将要正式介绍的语义 ID 放进同一张表里：

**表 2-1　三种物品标识方式对比**

| 维度 | 原子 ID（atomic） | 文本 ID（textual） | 语义 ID（semantic） |
|---|---|---|---|
| 代表工作 | YouTube DNN [REF-056] (2016) / 几乎所有传统深度推荐 | P5 [REF-011] (2022) | TIGER [REF-009] (2023) 起 |
| 词表规模 $\|V\|$ | $N \in [10^7, 10^{10}]$ | BPE 子词表（约 $5\times 10^4$） | $K \in [256, 1024]$ |
| token 序列长度 $L$ | 1 | 3–5（BPE 切分后） | 3–8（设计常数） |
| 单物品语义性 | 无 | 弱（仅字面） | 强（内容/协同语义） |
| 唯一性 | 严格 | 严格 | 设计上严格，工程中可能碰撞 |
| 泛化与冷启动 | 失效（无信息可复用） | 弱（仅依赖字面相似） | 较强（共享前缀码） |
| 可生成性 | 直接但词表爆炸 | 直接但长度方差大 | 直接且 $K^L\gg N$ 可控 |
| 存储开销 | $\mathcal{O}(Nd)$ 显存 | LLM 词表共享 | $\mathcal{O}(K\!\cdot\! L\!\cdot\! d)$ |
| 与传统 ANN 兼容 | 高 | 中 | 中（需 prefix-tree 约束解码） |

> **表 2-1 注释**：「碰撞（collision）」指两个不同物品被分配到完全相同的 $(c_1, \dots, c_L)$，详见 §2.2 的 RQ-VAE 多层量化设计。「prefix-tree 约束解码」是为了保证生成序列对应实际存在物品的工程手段，详见第 3 章。

读完表 2-1，语义 ID 相对于另外两种方案的设计逻辑就非常清楚了：**它要在一个固定的小词表 $V$（$|V|=K$）上，通过 $L$ 层组合把容量推到 $K^L\geq N$；同时让相邻 token 携带语义信息（相似物品共享前缀），并保证整段序列的长度与组合规则可被自回归模型直接解码**。下一小节给出这一设计目标的形式化版本。

## 2.1.4　语义 ID 的设计目标：四位一体

回到工程语言，语义 ID 之所以成为生成式推荐的「词表底座」，是因为它同时满足以下四个互相约束的设计目标。这四点不是先天给定的，而是 2022—2026 年间一系列工作（DSI、P5 [REF-011]、TIGER [REF-009]、LETTER、DIGER [REF-072]、CapsID [REF-073]、Snapchat SID 实践 [REF-074]）反复迭代后凝聚出的共识。

**目标一：语义保真（fidelity）。** 物品 $i$ 的语义 ID $(c_1, \dots, c_L)$ 应当尽可能保留 $\mathbf{e}_i$ 中的关键信息——内容相似的物品应当共享前缀，模态接近的物品应当在码本空间中聚簇。形式化地，这一要求可以写成「给定原始 embedding $\mathbf{e}_i$，存在解码器 $g$ 使得 $g(c_1, \dots, c_L) \approx \mathbf{e}_i$」。这是 VQ-VAE [REF-008] 在 2017 年提出的最初动机，也是后续 RQ-VAE 在推荐中复用的核心损失项（§2.2 详述）。

**目标二：压缩率（compactness）。** 在保真前提下，语义 ID 应当用尽可能小的 $|V|$ 与 $L$ 完成对 $\mathcal{I}$ 的覆盖——这与公式 (2.2) 的组合放大思路一致：宁可用 $K=256, L=4$ 覆盖 $4\times 10^9$ 物品，也不要用 $K = N, L = 1$ 直接退化为原子 ID。这一目标的工程含义是显存占用降到 $\mathcal{O}(KLd)$ 而非 $\mathcal{O}(Nd)$；当 $N=10^9$、$d=64$ 时，原子 ID 方案需要数百 GB 显存，而语义 ID 方案仅需 MB 级。

**目标三：唯一性（uniqueness）。** 不同物品应当被分配到不同的 $(c_1, \dots, c_L)$。在严格意义上，唯一性要求 $K^L\geq N$，但只要分配过程是「最近邻 + 随机平局打破」，就不能完全杜绝碰撞——两个内容几乎一致的物品（如同一商品的两个 SKU 版本）天然倾向于被分到同一码字。工业实践中通常采用「主语义 ID + 末位唯一性后缀」的组合（如 $L+1$ 层，前 $L$ 层做语义、最后一层做去重 hash）来保证唯一性，TIGER [REF-009] 与 Snapchat [REF-074] 都采用了类似策略。

**目标四：可生成性（generability）。** 语义 ID 必须能被自回归模型逐 token 解码——即在每一步 $k$，模型对 $V$ 上的所有 $K$ 个 codeword 计算条件概率 $p_\theta(c_k\mid c_{<k}, s_u)$ 并采样。这一要求与目标一—三相互制约：$L$ 太大会拉长解码延迟、$K$ 太小会损失保真度、码本设计若不规整会导致大量「合法序列对应空物品」。第 3 章会专门讨论 prefix-tree 约束解码、speculative decoding 等保证可生成性的工程技术。

把四个目标合起来看，「语义 ID」其实就是**一个被精心设计的离散瓶颈（discrete bottleneck）**：它一方面足够小（满足 $K^L$ 这种紧凑组合容量），另一方面又足够富（满足语义保真），同时还能被高效地学习（VQ 系列损失、Gumbel 重参数化、协同正则）和高效地生成（约束解码、speculative decoding）。这种「在四个相互拉扯的目标之间找平衡」的工程艺术，正是第 2 章后续五节（§2.2-§2.6）的全部内容。

读到这里，可以正式给出本节的核心定义：

> **定义 2.1（语义 ID, Semantic ID）**　给定物品空间 $\mathcal{I}$、码本 $V$（$|V|=K$）与层数 $L$，物品 $i$ 的**语义 ID** 是一个有序离散序列 $\sigma(i) = (c_1, c_2, \dots, c_L) \in V^L$，且映射 $\sigma: \mathcal{I}\to V^L$ 同时满足语义保真、压缩率、唯一性、可生成性四项设计目标。当 $\sigma$ 由可学习的 VQ 类编码器（如 RQ-VAE）从物品的内容或协同向量 $\mathbf{e}_i$ 中量化得到时，称为狭义语义 ID；当 $\sigma$ 由 LLM 直接生成的可读文本（如属性串）拼接时，称为广义语义 ID（详见 §2.5）。

后续章节中除非特别说明，「语义 ID」一律指**狭义语义 ID**——也就是由 VQ 类方法量化得到的离散码序列。

## 2.1.5　从两阶段到联合优化：语义 ID 的两代演进概览

把镜头拉到 2022—2026 年的研究主线上，语义 ID 大致经历了**两代演进**。

**第一代（2022—2024）：两阶段 + 冻结。** 以 TIGER [REF-009] 为代表，整个流程分两段：先用 RQ-VAE 在物品内容 embedding 上学一个码本、把所有物品的语义 ID 算出后冻结；再训练 T5 风格的 seq2seq 推荐器，以用户行为序列为输入、目标物品的语义 ID 为输出。优点是结构清晰、可分别优化；代价是**索引损失（reconstruction）与推荐损失（next-item prediction）目标错位**——tokenizer 只看内容、不知道协同信号，推荐器学到的偏好也无法反向更新 ID。这种「先学好再冻结」的范式让早期工业落地（如 OneRec 早期版本、Snapchat SID v1 [REF-074]）能够快速上线，但 2024 年后被视为有改进空间的基线。

**第二代（2025—2026）：可微分 + 联合优化。** 代表性工作是 **DIGER（Fu 等，SIGIR 2026）[REF-072]**：据其 SIGIR 2026 摘要逐字描述，DIGER 把语义索引改造为**可微分语义 ID（differentiable semantic ID）**——通过 Gumbel 噪声引入早期阶段的码本探索（early-stage exploration over codes），用两种不确定性衰减策略（uncertainty decay strategies）实现从探索到利用的平滑过渡，让推荐损失可经 SID 模块直接反向传播到 tokenizer，从而**对齐索引与推荐目标**；论文报告在多个公开数据集上获得一致提升，并将其作为「可微分语义索引这一新研究方向的第一步」。第二代的另一条平行支线是**软路由 + 可变长度**——**CapsID（Cheng 等，2026-05）[REF-073]** 用胶囊路由替代 RQ-VAE 的硬最近邻分配，每层物品概率性路由到多个语义胶囊，并以自适应信心阈值决定 ID 长度；论文报告 Recall@10 较最强基线 +9.6%、推理延迟约为稀疏-稠密混合系统的 51%。需要提示的是，CapsID 截至本节写作时（2026-05）刚发布于 arXiv（编号 2605.05096），尚未有顶会同行评审录用信息，结论以原文为准。

工业落地视角上，**Snapchat SID 实践（Ju 等，SIGIR 2026 Industry Track）[REF-074]** 给出了首份系统的语义 ID 工业部署经验报告：RQ-VAE tokenizer 同时被用作排序模型的离散特征与生成式召回的解码词表，论文系统总结了码本坍缩、码本规模与层数选型、在线 A/B 实验设计等技术挑战与设计选择。这类工业报告对工程读者比纯学术 SOTA 更有参考价值——它告诉读者哪些细节在 paper 里被忽略、上线时却必须解决。**Item ID 综述 [REF-071]（Zhang 等，HKBU 2026 TechRxiv）** 把所有这些工作纳入一个三维框架——*Construction*（数值/文本/多面/语义 ID 及标记化方法）、*Alignment*（协同/多模态对齐）、*Generation*（直接生成/约束解码/解码加速），与本书第 2 章 §2.2-§2.6 的章节切分高度同构，读者后续可把它当作一张「速查地图」。

> **本节最新进展（2024—2026）**：① DIGER（SIGIR 2026）[REF-072] 首次实现语义 ID 可微分联合优化，对齐索引与推荐目标；② CapsID（2026-05）[REF-073] 用胶囊路由实现可变长度语义 ID，Recall@10 +9.6%；③ Snapchat SID（SIGIR 2026 Industry）[REF-074] 给出首份语义 ID 工业部署经验报告；④ Item ID 综述（2026 TechRxiv）[REF-071] 提出 Construction × Alignment × Generation 三维框架。这四项标志着语义 ID 从「为生成而生的工具」演进为独立的研究子领域。

## 2.1.6　本节小结与第 2 章路线预告

本节用四步回答了「为什么需要离散化物品表示」——§2.1.2 从公式 (2.1) 论证自回归生成机制对有限离散词表的强制性要求，并通过公式 (2.2) 与组合容量 $K^L$ 说明连续 Embedding 直接生成不可行；§2.1.3 用表 2-1 把原子 ID [REF-056] 与文本 ID [REF-011] 作为对照，标出两者在工业规模下的局限；§2.1.4 给出语义 ID 的四位一体设计目标（语义保真、压缩率、唯一性、可生成性）与定义 2.1；§2.1.5 从研究主线视角梳理两代演进，标出 DIGER [REF-072]、CapsID [REF-073]、Snapchat SID [REF-074] 等 2026 年前沿方向。一句话总结——**生成式推荐之所以离不开语义 ID，是因为自回归解码的数学本质要求一个有限离散词表，而工业级物品规模又强迫这个词表必须以「小码本 × 多层组合」的方式构造，并同时承载语义、压缩、唯一、可生成四重诉求**。

第 2 章接下来的五节将依次解答「怎么做」：**§2.2** 把 VQ-VAE [REF-008] 的码本机制与直通估计器讲透，再过渡到 RQ-VAE 的多层残差量化（TIGER [REF-009]、Snapchat SID [REF-074] 共同的方法基线）；**§2.3** 讨论 LETTER 等工作如何在 RQ-VAE 中加入协同正则，缓解码本坍缩；**§2.4** 正式展开 DIGER [REF-072] 的 Gumbel 重参数化与不确定性衰减细节；**§2.5** 把视角切到 LLM 路线下的广义语义 ID（IDGenRec、可读属性串等）；**§2.6** 借 Snapchat SID 实践 [REF-074] 把所有方法落到工程视角。

下一节（§2.2）将从 VQ-VAE [REF-008] 的码本机制出发，先回答最基础的工程问题——**给定一组连续向量 $\{\mathbf{e}_i\}_{i\in\mathcal{I}}$，如何把它们一一映射到一个固定大小为 $K$ 的码本、并保留尽可能多的语义保真度？** 解决了「为什么」之后，§2.2 将深入解答「怎么做」——向量量化（VQ）及其残差扩展（RQ-VAE）是目前最成熟的技术路径，也是后续所有语义 ID 工作的方法地基。
