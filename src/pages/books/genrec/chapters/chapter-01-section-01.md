# 1.1　传统推荐系统的核心架构

## 1.1.1　本节定位与问题提出

本节是全书的起点，也是后续所有生成式方法的参照系。在进入"生成式推荐（Generative Recommendation）"之前，我们需要先把"传统推荐系统（Conventional Recommender Systems）"的骨架拆开摆在桌面上——它是怎样从亿级候选库中为每一位用户挑出几十条内容的？它在过去二十年里形成了哪些牢不可破的工程范式？又是在哪些根本问题上遭遇了瓶颈？

回答这三个问题，是理解后续章节的前提。本节不追求穷尽历史细节，而是希望建立一张读者可以反复回头对照的"历史坐标系"：一端标注传统推荐的**级联漏斗架构（Cascade Funnel Architecture）**，另一端标注它所依赖的**基于 ID 的嵌入表示体系（ID-based Embedding）**。这两点是传统推荐的"承重墙"，也是生成式推荐试图替换掉的那两堵墙。

本节假设读者已了解矩阵分解、神经网络、自注意力等基础概念；若需要更细的数学推导，可参阅《推荐系统实践》等入门教材。本节重点回答五个问题：①级联漏斗包含哪几层、各层规模与目标是什么；②为什么业界公认"召回是系统天花板"；③基于 ID 的嵌入表示有哪些固有局限；④多阶段架构中的"目标割裂"与"误差级联"具体如何发生；⑤传统架构与生成式架构的本质差异何在。前四个问题构成本节主体，第五个问题作为结尾的引子，为 §1.2 之后的内容做铺垫。

## 1.1.2　技术演进时间线：从 ItemCF 到万亿参数 Transducer

为了让读者对"时间感"有一个直观印象，图 1-1 给出了推荐系统三十年的主要里程碑。这里只列出与本章论述相关的关键事件，并不代表全部进展。

**图 1-1　传统推荐系统三十年演进时间线（示意）**

```
1994 ── GroupLens 提出协同过滤（CF）范式
1998 ── Amazon 规模化部署 ItemCF
2008 ── 加权矩阵分解处理隐式反馈                  [REF-001]
2010 ── 矩阵分解成为推荐主流
2013 ── Item2Vec 借鉴 Word2Vec，物品向量化兴起
2016 ── YouTube DNN 双塔工业落地                   [REF-056]
2017 ── NCF 证明深度学习在 CF 上的有效性           [REF-002]
2017 ── Transformer 发布                           [REF-005]
2018 ── DIN 注意力机制用于 CTR 精排                [REF-004]
2018 ── SASRec 自注意力用于序列推荐                [REF-003]
2019 ── BERT4Rec 双向 Transformer 建模行为序列
2020 ── 双塔 + ANN 成为向量召回事实标准
2022 ── P5 尝试用 T5 统一推荐任务（范式转折前夜）
2023 ── TIGER 生成式召回范式诞生（超出本节范围）
2025 ── OneRec 端到端生成式推荐工业部署
```

这条时间线大致可以划分为三个时期。**第一期（1994—2010）**是以协同过滤和矩阵分解为主的"统计/线性时代"，核心是从用户-物品交互矩阵中恢复低秩结构。**第二期（2010—2022）**是"深度学习时代"，双塔模型、注意力机制、序列 Transformer 轮番登场，在同一套"召回→排序"两阶段蓝图内不断加深模型表达能力。**第三期（2022 年至今）**是"生成式转折期"，P5、TIGER、HSTU、OneRec 等工作开始质疑两阶段范式本身——但这已经是 §1.2 之后要展开的故事。本节聚焦前两个时期，它们共同塑造了今天绝大多数工业推荐系统的样子。

值得指出的是，尽管 2024 年之后生成式推荐论文大量涌现，**传统级联架构至今仍是主流工业推荐的底层骨架**。理解这副骨架的构造与力学弱点，是判断一项生成式新方法"究竟在替换哪块承重墙"的唯一途径。

## 1.1.3　级联漏斗：为什么推荐系统长成了今天这样

### （一）动机：毫秒级响应与亿级候选的矛盾

一个中大型推荐平台的候选物品常在千万乃至数十亿量级，而线上服务的端到端延迟预算只有几十到一百多毫秒。这种"候选规模—延迟预算"的巨大落差，使得单一模型不可能同时做到两件事：既对所有候选逐一打分（精度优先），又保证毫秒级返回（效率优先）。工业界的解决方案是**分阶段筛选**：用若干级联的模型把候选集合逐层缩小，每级模型的复杂度与其所面对的候选规模相匹配。这就是级联漏斗（cascade funnel）的根本动机，它不是某篇论文的发明，而是工程约束倒逼出的事实标准 [REF-057]。

### （二）四层漏斗的规模与目标

图 1-2 给出了典型级联漏斗的数据流与规模变化。

**图 1-2　典型级联漏斗架构的数据流与候选规模（示意）**

```
          候选物品池  (10^7 ~ 10^9)
                │
                ▼
   ┌───────────────────────────┐
   │  召回 Recall               │   多路异构通道并行
   │  ItemCF / UserCF / 双塔ANN│   单路 O(10^2 ~ 10^3)
   │  内容召回 / 热门 / 兴趣    │   合并 O(10^3 ~ 10^4)
   └───────────────────────────┘
                │
                ▼     [千级候选]
   ┌───────────────────────────┐
   │  粗排 Pre-Ranking          │   轻量双塔 / 浅层交叉
   │  DSSM / COLD / FSCD 等     │   目标：快速缩候选
   └───────────────────────────┘
                │
                ▼     [百级候选]
   ┌───────────────────────────┐
   │  精排 Ranking              │   DIN / DIEN / Transformer
   │  多目标建模 CTR/CVR/时长   │   目标：精确打分
   └───────────────────────────┘
                │
                ▼     [十级候选]
   ┌───────────────────────────┐
   │  重排 Re-Ranking           │   多样性 / 时效性 / 业务规则
   │  MMR / DPP / 业务约束      │   目标：列表级优化
   └───────────────────────────┘
                │
                ▼     [最终曝光列表]
```

四层阶段的职责与工程约束可以这样概括。**召回（Recall）**的目标是在亿级候选中"找到候选集"，要求尽可能高的相关物品覆盖率，因而延迟预算最紧，通常只能负担简单的向量相似度或哈希索引。**粗排（Pre-Ranking）**是召回与精排之间的缓冲带，它要对千级候选做一次轻量打分，把候选进一步压缩到百级；其模型结构通常是精排的"瘦身版"，典型代表是阿里的 COLD 系列与各大平台的双塔粗排。**精排（Ranking）**是整个系统最复杂的环节，模型可以消耗大部分延迟预算，引入用户历史序列、上下文特征、候选物品侧特征的高阶交叉，对 CTR、CVR、停留时长等多目标同时建模；DIN [REF-004] 及其后继就工作在这一层。**重排（Re-Ranking）**不再针对单个物品打分，而是把精排得到的候选视为"待编排的一列商品"，在列表层面考虑多样性、疲劳度抑制、商业规则（广告位、流量扶持）等。四层从上到下候选数减少 4—6 个数量级，模型复杂度递增，这是级联漏斗最重要的"数量—精度"分布规律。

### （三）向量召回与双塔：现代召回的工业基线

在召回阶段的多条通道中，**基于双塔模型的向量召回**是最接近"现代工业基线"的一条。其思想可以类比为图书馆检索：在正式查阅之前，先在总目录卡片上按关键词粗筛出一叠候选书籍。推荐系统的"关键词"是连续向量，而"总目录"就是预先离线构建好的物品向量索引。

YouTube 2016 年的工作 [REF-056] 奠定了这一范式。它由两座独立的神经网络塔组成：User Tower 把用户特征（观看历史、人口属性、上下文）映射为用户向量 $\mathbf{u} \in \mathbb{R}^d$，Item Tower 把物品特征（视频 ID、类目、标题词袋）映射为物品向量 $\mathbf{v} \in \mathbb{R}^d$。在线服务时，系统对每个请求实时计算用户向量，再通过近似最近邻（Approximate Nearest Neighbor, ANN）索引（如 Faiss、ScaNN、Milvus）在物品向量空间中检索最相近的若干项。打分公式非常简洁——先看公式中的符号：$\mathbf{u}$ 为用户塔输出的向量，$\mathbf{v}_i$ 为第 $i$ 个物品塔输出的向量，内积用于衡量用户与物品在共享语义空间中的相似度：

$$
\hat{r}_{ui} = \mathbf{u}^{\top} \mathbf{v}_i. \tag{1.1}
$$

公式 (1.1) 的物理含义是：用户与物品在同一个 $d$ 维空间中各自有坐标，二者夹角越小（内积越大），越值得被推荐。之所以整条工业链路都围绕"内积"这一形式展开，是因为内积可以直接对接成熟的 ANN 索引：离线把所有物品向量灌入索引，在线仅需检索 Top-K 近邻，复杂度近似 $O(\log N)$，从而让"在千万候选里做召回"这件事在几毫秒内完成。

### （四）协同过滤的公式化：从显式到隐式

向量召回之所以能把"用户—物品相似度"写成一次内积，更深层的数学根源来自矩阵分解。传统协同过滤的标准优化问题可以写作：

$$
\min_{P,Q} \sum_{(u,i)\in \mathcal{R}} c_{ui} \big( r_{ui} - \mathbf{p}_u^{\top} \mathbf{q}_i \big)^2 + \lambda\big(\|P\|_F^2 + \|Q\|_F^2\big). \tag{1.2}
$$

公式 (1.2) 中，$\mathbf{p}_u \in \mathbb{R}^d$ 与 $\mathbf{q}_i \in \mathbb{R}^d$ 分别为用户与物品的低维隐向量，$r_{ui}$ 为观察到的交互强度（例如是否点击、观看时长等隐式信号），$c_{ui}$ 是 [REF-001] 提出的"置信度权重"——越强的行为赋予越高的 $c_{ui}$，而缺失交互被赋予一个较低但非零的权重，代表"未必不感兴趣"。最后一项 $\lambda(\|P\|_F^2 + \|Q\|_F^2)$ 是 Frobenius 范数正则项，用于抑制过拟合。

这个式子的意义超出了 2008 年本身：它把"偏好"定义为向量在低维空间中的位置关系，把"预测"定义为内积，把"训练"定义为带权重的平方损失。后来的 NCF [REF-002] 用 MLP 替换了内积以拟合更复杂的非线性交叉，再后来的双塔模型则把 $\mathbf{p}_u$、$\mathbf{q}_i$ 的计算交给了神经网络。但"用户—物品内积"的基本骨架一直保留到今天，也正因如此，传统召回天然地与 ANN 索引匹配。这是理解 §1.2 及其后序章节的一个关键伏笔。

### （五）序列建模：从 GRU4Rec 到 SASRec

除了从交互矩阵中学习静态偏好，工业系统还关心"最近 50 次点击"这样的动态信号。2018 年的 SASRec [REF-003] 在这一条线上最具代表性，它把只使用下三角掩码的单向 Transformer 用于物品序列，以最后一个位置的隐向量预测"下一步最可能点击的物品"。其核心是标准的缩放点积注意力：

$$
\mathrm{Attention}(Q, K, V) = \mathrm{softmax}\!\left(\frac{Q K^{\top}}{\sqrt{d_k}}\right) V. \tag{1.3}
$$

这里 $Q, K, V$ 均来自于同一条物品序列的线性映射，$d_k$ 是每个注意力头的维度。公式 (1.3) 沿用了 Transformer 的原始形式 [REF-005]，其数学意义是：每一个位置的输出是"整条历史序列的加权求和"，而权重由该位置与其他位置之间的相似度决定。SASRec 的意义不在于引入 Transformer 本身，而在于证明了"自注意力 + 下一个物品预测"这一组合在推荐任务上同时超越 GRU 与 CNN 系列。这一结论后来被 BERT4Rec 扩展到双向，被 DIN/DIEN [REF-004] 推广到精排侧的用户兴趣建模。从此，**"序列 + 注意力"与"双塔 + 向量检索"并列为深度推荐时代的两条主脉络**，分别占据精排与召回的主战场。

### （六）"召回是天花板"的工程含义

把上面几小节的论述串起来，就得到推荐系统工程实践中的一个长期共识：**在级联漏斗中，召回阶段决定了整个系统的性能上限**。因为被召回阶段丢弃的物品不再进入后续打分，即使精排模型准确率达到理论上限，它也无法把一个从未被召回过的商品重新捞回来。换言之，召回的召回率（Recall@K）是整个级联的"信息瓶颈"，而精排只是在已经丢失信息的候选集中做相对排序。这一立场也得到 [REF-057] 这篇 2024 年系统综述的呼应——文中明确指出"若没有有效的检索，即便最先进的后续阶段也无法达到最优表现"，并由此把召回方法独立成研究对象，按"相似度—索引—训练"三个维度系统梳理。工业实践中的一个折中手段是**多路召回（multi-channel retrieval）**：协同过滤通道提供个性化、双塔向量通道提供精准匹配、热门/新品通道提供多样性，再在粗排阶段合并。这一折中缓解了单路召回率的上限问题，但并未从根本上消除"级联=信息单向传递"带来的结构性损失。

## 1.1.4　基于 ID 的嵌入表示：光环之下的五个裂缝

如果说级联漏斗是传统推荐的"骨骼"，那么**基于 ID 的嵌入表示（ID-based Embedding）**就是它的"神经"。几乎所有上一小节出现的模型——从矩阵分解到双塔、从 SASRec 到 DIN——都共享同一种物品表示方式：为每个物品分配一个唯一整数 ID，并为该 ID 学习一个 $d$ 维稠密向量。这种做法的直觉类比是：图书馆给每本书贴一个完全随机的条形码，图书的内容、作者、主题都不参与编码，条形码之间的"远近"只能通过借阅行为事后学习。

这种 ID 表示在"封闭域、数据丰富、分布稳定"的场景下运作得相当好。但随着业务规模扩大、冷启动比例上升、跨端跨域需求出现，它暴露出五个日益明显的裂缝：

1. **冷启动严重**。新物品尚无交互历史，随机初始化的 ID 向量得不到监督信号，只能依赖启发式规则或内容旁路曝光；这在短视频、电商新品场景尤其棘手。
2. **跨域不可迁移**。A 平台学到的物品 ID 向量对 B 平台完全无意义，因为两套 ID 空间之间没有任何对齐。工业界为此发展出 UniSRec 等"通用序列表示"思路（详见第 8 章），但迁移的代价始终不低。
3. **缺乏语义**。纯行为信号无法告诉模型"《星际穿越》与《火星救援》同属硬科幻"；模型只能在用户恰好连续看过这两部电影时才把它们拉近。相较之下，人类在没有任何共同观众的情况下也能判断两部电影相关。
4. **数据孤岛**。ID 绑定平台，平台之间、业务线之间不可共享。即使在同一家公司内部，搜索与推荐、短视频与图文通常也各自维护自己的 ID 体系。
5. **泛化性差**。ID 表示不能直接用于摘要生成、推荐理由生成、用户画像刻画等下游任务，因为它没有可解释的语义轴。

这五个问题彼此相关，根源都指向一件事——ID 是**符号（symbol）**而非**内容（content）**，它不携带关于物品本身的任何信息，只有"别人是否和它一起被点过"这一种外部证据。正是这一点，让 §1.3 之后"用文本 token 或语义 token 替换物品 ID"的各类方案具备了合法的动机。

## 1.1.5　目标割裂与误差级联：漏斗架构的两个内在裂缝

即使暂时搁置 ID 表示问题，只看级联漏斗本身，它也有两处结构性缺陷。

**目标割裂（Objective Misalignment）**。召回、粗排、精排通常由不同团队独立维护，训练目标也各不相同：召回通常用 sampled softmax 或 BPR loss 学习"用户—正例—负例"的相对顺序；粗排常用轻量 CTR 或蒸馏损失做分类；精排则是多任务学习，CTR、CVR、时长等目标各有各的交叉熵或回归损失。每一层都在优化"自己那一层的局部目标"，但整个漏斗真正面对的业务指标（留存、LTV、GMV）并不是任何一层的直接目标。结果是：即便各阶段单独测试指标都在涨，级联串联后的线上指标反而可能持平或下降。这种现象被业界俗称为"单点上涨、系统不动"。

**误差级联传播（Error Propagation）**。漏斗每一层都是"单向不可逆"的：被召回过滤掉的物品不会出现在粗排里，被粗排过滤掉的物品不会出现在精排里。任何一层的偏差（例如热门偏差、样本偏差、曝光偏差）都会被下游继承并可能放大。一个具体的例子：若召回阶段的双塔模型对冷门品类的相关性预估系统性偏低，则冷门品类的优质商品几乎无法进入精排视野，进而无法获得曝光，缺曝光又会导致后续训练数据中冷门品类样本继续稀缺，形成负反馈闭环。这是推荐系统公平性、多样性与长尾问题的结构性根源之一。

这两个裂缝在 2020 年之前并非没有被察觉，工业界也有"端到端蒸馏""联合训练"等部分回应，但真正系统性的重写——把"召回—排序"替换为"单模型一次自回归生成"——要等到 2023 年之后的 TIGER、HSTU、OneRec 等工作才出现。这正是第 4 章"端到端统一框架"的主战场。

## 1.1.7　小结与本节要点

本节以"级联漏斗 + ID 表示"为双坐标轴，重建了传统推荐系统的核心架构，并围绕五个关键问题做了回答：

- **Q1 级联漏斗的四层结构**：召回 O(10^3—10^4) → 粗排 O(10^2) → 精排 O(10) → 重排 → 曝光；数量递减、模型复杂度递增，这是候选规模与延迟预算共同约束下的工程产物。
- **Q2 "召回是系统天花板"**：由于漏斗的单向性，召回阶段的召回率直接决定了整个系统的性能上限，精排只能在已损失信息的候选集中做相对排序——这一工程含义在 [REF-057] 中被概括为"若没有有效的检索，即便最先进的后续阶段也无法达到最优表现"。
- **Q3 ID-based Embedding 的本质与局限**：把物品当作无语义的符号 ID，以行为共现为唯一学习信号；由此派生出冷启动、跨域、语义、孤岛、泛化五大裂缝。
- **Q4 目标割裂与误差级联**：各阶段局部优化与业务整体目标不一致；上游偏差在漏斗中不可逆地放大，形成对长尾与多样性的系统性压制。
- **Q5 传统架构与生成式架构的本质差异**：传统架构把"从候选库中挑出 Top-K"问题分解为"多阶段判别式打分"；生成式架构则尝试把它重写为"一次性自回归生成物品标识"——架构哲学从"逐层筛选"转为"直接生成"。

**最新进展（2024—2026）**。虽然传统级联架构仍是工业主流，但 2024 年之后有几条线索值得持续关注：①[REF-057] 在 2024 年首次系统性地把"召回"作为独立研究对象提出三维分类框架，标志着学术界开始补齐这块长期被低估的版图；②2025 年 OneRec [REF-018]、OneSearch [REF-049]、HSTU [REF-051] 等端到端生成式工作在快手、美团、Meta 等头部平台先后上线，验证了"用单模型替代级联链路"在工业规模下的可行性；③2026 年 RecoChain（arXiv:2604.25787，待登记 REF-059）等工作进一步指出，生成式推荐内部也会出现"有召回无排序"的新级联问题，这是级联思想在生成式范式下的再生变体。这些最新进展提示我们：**级联并非绝对过时，ID 也并非必须取代——真正推动生成式推荐登场的，是传统架构在冷启动、跨域、多模态、统一优化这四个方向上的承载力极限**。

下一节将沿时间轴把视角聚焦到"深度学习时代"：在 2013—2022 这十年间，推荐系统是如何在不改变级联骨架的前提下，通过表示学习与序列建模把模型能力推到极致，又是在什么样的边际收益递减下迎来生成式转折的。
