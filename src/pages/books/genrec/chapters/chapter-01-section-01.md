# 1.1 推荐系统 60 年简史：规则 → 协同过滤 → 深度学习 → 生成式

## 1.1.1 引子：为什么要从 60 年前讲起

谈"生成式推荐"，几乎所有的综述都会从 2022 年的 P5 [REF-040] 或 2023 年的 TIGER [REF-010] 起笔。这种"从转折点开始讲故事"的写法节省篇幅，却也容易让读者产生一种错觉——以为生成式推荐只是把大语言模型挪到了推荐场景，是"深度学习推荐 2.0"。本书选择从更早的位置切入：把时间拉回到 1960—1970 年代的早期信息过滤实验，把"生成式"放回到推荐系统六十年的演进谱系中观察。

这样做的目的并不是怀旧。推荐系统经历了"规则 → 协同过滤 → 深度学习 → 生成式"三次大的范式更替。每一次更替，外在表现都是模型变复杂、效果变好，但**内在驱动力**却是同一条主线——**让"推荐什么给谁"这件事，越来越多地由数据自身的统计规律来决定，越来越少地依赖人工先验**。生成式推荐之所以重要，不在于它用了 Transformer 或扩散模型，而在于它在这条主线上又往前推了一步：连"输出物品"这件事本身，也开始由模型一次性生成，而不是从人工候选池里挑出来。看清这条主线，才能在后续章节中既保持对新方法的敏感，又不被术语的浪潮裹挟。

本节的目标只有一个：用一节的篇幅，建立读者对"为什么推荐正在转向生成式"的直觉，并给出本书将在第 12 章末尾才再次回顾的"生成式推荐工作定义"。关于具体方法的展开，从第 2 章开始。

## 1.1.2 四个阶段的概览

为方便后文反复引用，先用一张表把六十年的主要节点摆出来。表中的"局限"一列，正是下一阶段技术兴起的"动机"。

| 时期 | 代表范式 | 技术标志 | 局限 |
|------|----------|----------|------|
| 1960s—1990s：规则与知识驱动期 | 基于规则的过滤、基于内容的匹配 | Grundy（1979）、Tapestry（1992） | 手工规则，不可扩展 |
| 1990s—2010s：协同过滤主导期 | User-based / Item-based CF、矩阵分解（MF）、BPR | Amazon item-to-item（2003）、Netflix Prize（2006—2009） | 数据稀疏、冷启动、线性建模 |
| 2010s—2022：深度学习范式期 | Wide&Deep、DIN、DeepFM、双塔、SASRec / BERT4Rec | YouTube DNN（2016）、DIN（2018） | 多阶段级联、特征工程重、撞 scaling 天花板 |
| 2022—至今：生成式范式期 | 自回归生成、扩散生成、LLM4Rec、端到端大模型 | P5（2022）、TIGER（2023）、HSTU（2024）、OneRec（2025） | 语义 ID 设计、对齐、评测、幻觉 |

### 第一阶段：规则与知识驱动（1960s—1990s）

最早的推荐系统并不叫"推荐系统"。1979 年的 Grundy 试图根据用户描述匹配小说，依靠的是手工编写的"刻板印象（stereotype）"规则；1992 年 Xerox PARC 的 Tapestry 第一次提出了"协同过滤（collaborative filtering）"一词，但其底层仍然是一套基于用户标注与查询的规则系统。这一时期的方法效果今天看十分朴素，但它**确立了推荐系统的基本输入输出范式**——给定用户与上下文，从一个候选集中选出若干项呈现给用户。这个"打分—排序—呈现"的输出形态，会一直延续到深度学习时代结束。

### 第二阶段：协同过滤主导（1990s—2010s）

进入互联网时代，规则系统迅速被数据驱动方法取代。两条主线交织发展：一是 Amazon 在 2003 年公开的 item-to-item 协同过滤，把推荐做成了大型电商的标配能力；二是 2006—2009 年的 Netflix Prize，把矩阵分解（MF）和后来的 BPR 等方法推到了学术与工业的中心。这一时期最大的遗产，是"**用相似度取代规则**"的思想——无论是用户—用户、物品—物品的近邻，还是隐因子空间里的内积，本质都是从交互数据中学到一组可计算的相似度，再用相似度替代手写规则去决定推荐。

但协同过滤同时也埋下了一个技术债，并在二十年后才被正面回应：物品被表示成"原子 ID"——一个不可分解、彼此正交的整数。这个表示足以支撑相似度计算，却也意味着**任何新出现的物品，因为没有 ID 也就没有交互记录，必须从冷启动开始重新学习**。生成式推荐对 Semantic ID（第 2 章）的重视，正是要直接拆掉这一债务。

### 第三阶段：深度学习范式（2010s—2022）

2016 年前后，深度学习进入推荐主战场。YouTube DNN（2016）将推荐拆成"召回 + 排序"两段并各自上深度模型；Wide&Deep（2016）把记忆与泛化分别交给宽线性部分和深网络部分；DIN（2018）用 attention 解决了用户兴趣的多峰建模；SASRec（2018）和 BERT4Rec（2019）把 Transformer 引入序列推荐，开始让"用历史行为预测下一次点击"逼近自然语言中的"下一个 token 预测"。从工程视角看，这是推荐系统效果迭代最快的十年，也是工业架构最复杂的十年——召回、粗排、精排、重排、多目标融合，每一层都堆叠了独立的特征体系与模型。

但临近 2022 年，深度学习推荐撞到了三堵墙：

1. **特征异质**：推荐场景的特征基数高、类型杂、半数以上是高基数稀疏 ID，难以用统一的 token 表示，使得 Transformer 在推荐里的"自然"使用方式与在 NLP 中差异巨大；
2. **多阶段级联**：召回与排序的优化目标不一致，离线指标提升常常无法线性传导到线上效果；
3. **scaling 天花板**：DLRM 类模型即使把参数堆到千亿规模，质量也很难随算力呈幂律增长，这与同一时期 LLM 表现出的清晰 scaling law [REF-030] 形成了刺眼的对照。

这三堵墙合起来，就是下一阶段"生成式"登场的全部理由。

## 1.1.3 生成式范式的转折点（2022—2025）

如果一定要给"生成式推荐"指定一个起跳年份，2022 年是最合适的选择。这一年同时出现了 P5 与 M6-Rec 两项工作，把推荐任务整体重铸成了"文本到文本"的生成问题。此后两年间，几条并行的技术线迅速汇流，把生成式推荐从一个学术口号发展成工业可用的范式。

- **P5（Geng et al., 2022）**：把序列推荐、评分预测、解释生成、评论生成、Top-K 推荐五类任务统一成 text-to-text 形式，用个性化提示词预训练，让单一模型覆盖多种推荐任务，是 LLM4Rec 路线的开山工作。[REF-040]
- **M6-Rec（阿里, 2022）**：在阿里 M6 大模型基础上，把召回、排序、零样本推荐、解释、内容生成全部转写为文本任务，证明一个 foundation model 可以贯穿推荐全链路。[REF-041]
- **TIGER（Rajput et al., NeurIPS 2023, Google）**：用 RQ-VAE 把每个物品的内容嵌入逐层残差量化为一组 codeword 元组，称之为 Semantic ID，再用 Transformer 自回归地"生成"下一个物品的 Semantic ID。这意味着模型不再依赖"嵌入 + ANN 检索"的双塔范式，而是**直接生成目标物品的标识符**；并且因为 Semantic ID 由内容编码而来，对**没有任何历史交互的冷启动物品也能给出合理的检索结果**——这是双塔架构在原子 ID 下天然做不到的能力。[REF-010]
- **DiffRec（Wang et al., SIGIR 2023）**：把扩散模型引入推荐，先在用户的交互向量上加噪声，再训练去噪过程以重建用户偏好分布。它没有像 TIGER 那样改变物品的表示方式，而是**用扩散过程改造了用户偏好的生成过程**，成为"扩散流派"在推荐中的开山工作。[REF-050]
- **HSTU（Zhai et al., Meta, ICML 2024）**：把推荐重新表述为生成式的"序列转导（sequential transduction）"任务，并设计了专门处理高基数、非平稳流式特征的 HSTU 架构，将生成式推荐推到 **1.5 万亿参数**的规模，在 8192 长度序列上比基于 FlashAttention2 的 Transformer 快 5.3—15.2 倍，并在 Meta 平台的线上 A/B 测试中取得**关键指标 +12.4%** 的收益；更关键的是，论文首次在推荐侧验证了类 LLM 的 power-law scaling 规律，跨越三个数量级仍然成立。[REF-030]
- **OneRec / OneRec-V2（快手, 2025）**：用 Encoder-Decoder + MoE 的端到端生成式模型替代传统的"召回—粗排—精排—重排"级联，并在 V2 中进一步引入 DPO 类的偏好对齐，在快手 App 实际线上落地。据团队报告，整体推理效率较原级联架构有数量级的改善（详见第 8 章工业落地讨论）[REF-031] [REF-032]。

把这六项工作放在一起，可以看出**两条并行的路径**：一条是 P5 / M6-Rec / OneRec 沿用的"语言生成"路径，把推荐任务文本化、Token 化；另一条是 TIGER / HSTU 主张的"原生序列转导"路径，不依赖自然语言，但同样把推荐建模为对离散标识符的自回归生成。DiffRec 则代表了第三条尚未与前两者完全融合的"扩散"路径。本书将分别在第 3、4、5 章展开它们的技术细节。

需要立刻强调的一点是：上述工作在公开数据集和工业 A/B 测试上的提升各异，但**到 2026 年初为止，没有任何一项工作能宣称生成式推荐在所有场景全面超过精心调优的判别式系统**。许多场景——尤其是候选池规模有限、标签信号充足、对延迟极度敏感的搜索/广告精排——判别式深度模型仍然是首选。生成式推荐改变的是"上限"和"路径"，而不是"在每个具体业务上都立刻更好"。本书在第 12 章会重新回到这个判断；在此之前，请读者把它作为一个工作假设带在心里。

## 1.1.4 "生成式推荐"的工作定义

回到本节最核心的问题：与过去六十年的推荐系统相比，"生成式推荐"究竟在做什么不同的事？综合 [REF-001]、[REF-002]、[REF-003] 三篇综述给出的口径，本书统一使用以下工作定义：

> **生成式推荐（Generative Recommendation）**：以生成模型（自回归语言模型、扩散模型、或两者的组合）**直接输出目标物品的标识符（Semantic ID 或自然语言形式的物品描述）或推荐相关内容**（解释、文案、对话回复）的推荐范式；区别于传统判别式范式——后者从一个外部给定的候选池中，对每个候选打分并按分排序。

围绕这个定义，再用一张表对照判别式与生成式范式的六个维度，构成本节最常被后续章节引用的对照基准：

**表 1：判别式推荐 vs 生成式推荐的 6 维对比**

| 维度 | 判别式推荐 | 生成式推荐 |
|------|------------|------------|
| 输入 | 用户特征 + 候选物品特征对 | 用户的历史行为 / 上下文 / 提示 |
| 输出 | 候选物品的相关性分数 | 目标物品的标识符或推荐内容（文本/Semantic ID） |
| 训练目标 | 点击 / 转化等监督信号下的 pointwise / pairwise / listwise loss | 下一个 token / Semantic ID 的极大似然，或扩散去噪目标 |
| 候选池 | 必须显式提供候选池（召回阶段产出） | 候选池可隐式存在于模型词表中，或在解码时通过受限解码注入 |
| 可扩展性 | 链路复杂、阶段间目标割裂、易撞天花板 | 端到端建模，词表/Token 是统一接口 |
| 与算力的关系 | DLRM 类模型 scaling law 不显著 | 已在 [REF-030] 等工作上观察到跨三个数量级的幂律 scaling |

理解这张表，比记住任何一个具体方法的名字都重要。当读者在后续章节遇到一个新的生成式推荐方法时，可以试着把它放回这六个维度——大概率会发现，所谓"创新"集中在其中一两个维度上。

## 1.1.5 本书的三维视角与阅读路径预告

最后用两段话交代本书的组织方式。

为了避免"按时间排"或"按方法排"两种综述常见结构的弊端，本书借鉴 [REF-001] 提出的**"数据—模型—任务"**三维视角：第 2—3 章讨论生成式推荐如何**重塑数据表示**（以 Semantic ID 为代表）；第 4—7 章讨论各类**模型骨架**（自回归、扩散、LLM4Rec、Agent）；第 8—10 章讨论它在召回、排序、冷启动、多模态等**任务**上的具体形态；第 11—12 章讨论评测、对齐与未来方向。三个维度交叉成本书的整体路线图，会在 1.3 节给出更详细的导航图。

本书面向三类读者：研究者关心新方法与开放问题，可以按 1 → 2 → 3 → 4 → 5 → 11 → 12 的路径阅读；推荐系统工程师关心落地与性能，可以按 1 → 2 → 6 → 8 → 9 → 12 的路径阅读；技术决策者关心趋势与成本，可以只读 1 → 8 → 12 三章。具体阅读路径与依赖关系，将在 1.4 节给出。

## 本节要点

1. 推荐系统的演进可以归纳为四阶段：规则与知识驱动、协同过滤主导、深度学习范式、生成式范式；每一阶段的兴起都源自对上一阶段瓶颈的回应。
2. 协同过滤留下的最大遗产是"用相似度取代规则"；最大的债务是"原子 ID 不可外推"，后者直接催生了 Semantic ID 这一生成式推荐的核心构件。
3. 深度学习推荐撞到的三堵墙——特征异质、多阶段级联、scaling 受限——是 2022 年后生成式范式登场的直接动机。
4. 2022—2025 年间，P5、M6-Rec、TIGER、DiffRec、HSTU、OneRec 等工作沿"语言生成""原生序列转导""扩散"三条路径同时推进，把生成式推荐从学术构想推到了工业落地。
5. 本书统一使用的"生成式推荐"工作定义：**以生成模型直接输出目标物品标识符或推荐相关内容的推荐范式**。判别式推荐与生成式推荐的差异，集中体现为表 1 列出的六个维度。
6. 截至 2026 年初，生成式推荐尚未在所有场景全面超越判别式系统；它改变的是上限与路径，而不是任何具体业务上的立刻领先。
